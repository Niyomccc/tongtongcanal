# Feature: สร้างและแก้ไขอีเว้นต์ (Event Management)
Spec ID: SPEC-EVM-001 | Source: Use Case Specification UC-10 | Use case: UC-10
Owner: TBD | Status: Draft v2 | Updated: 2569-09-20

## Goal
ผู้จัดงานสร้าง แก้ไข และปรับปรุงข้อมูลอีเว้นต์ (รายละเอียด วัน เวลา สถานที่)
และข้อมูลที่บันทึกแสดงต่อผู้ชมและวงดนตรีได้อย่างถูกต้อง

## Scope
### In scope
- สร้างอีเว้นต์ใหม่ / แก้ไขอีเว้นต์เดิม โดยระบุรายละเอียด วัน เวลา และสถานที่
- ตรวจสอบข้อมูลก่อนบันทึก และยกเลิกก่อนบันทึก
- จำกัดสิทธิ์การแก้ไขเฉพาะผู้มีสิทธิ์
### Out of scope
- ดูรายละเอียดอีเว้นต์ (UC-02) | จัดตารางการแสดง (UC-11) | ประกาศข่าวสาร (UC-12)

## Constraints
- PRE-EVM-01 ผู้จัดงานเข้าสู่ระบบและมีสิทธิ์จัดการอีเว้นต์ (precondition)

## Requirements
- FR-EVM-01 ระบบต้องให้ผู้จัดงานเลือกสร้างหรือแก้ไขอีเว้นต์                           <- UC-10 main flow ขั้น 1
- FR-EVM-02 ระบบต้องให้ผู้จัดงานกรอกข้อมูลอีเว้นต์ และระบุวัน เวลา และสถานที่ โดยผู้จัดงานเลือกสถานที่จากรายการที่ Admin จัดการผ่าน UC-15 และกำหนดค่าเปิด/ปิดรับลงทะเบียนเข้าชมและสมัครวง รวมถึงจำนวนที่นั่งสำหรับการลงทะเบียนเข้าชมเท่านั้น <- UC-10 main flow ขั้น 2-3
- FR-EVM-03 ระบบต้องตรวจสอบข้อมูลก่อนบันทึก รวมถึงความครบถ้วนของข้อมูลและสถานะพร้อมใช้งานของสถานที่ โดยต้องไม่ยอมบันทึกเมื่อมีข้อมูลไม่ครบหรือสถานที่ไม่พร้อมใช้งาน <- UC-10 main flow ขั้น 4
- FR-EVM-04 เมื่อผู้จัดงานยืนยัน ระบบต้องตรวจสอบและบันทึกข้อมูลอีเว้นต์ในขั้นตอนเดียวกันเพื่อป้องกันการจองซ้อนพร้อมกัน <- UC-10 main flow ขั้น 5-6
- FR-EVM-05 ระบบต้องให้ผู้จัดงานยกเลิกก่อนบันทึกได้ โดยไม่เปลี่ยนแปลงข้อมูล             <- UC-10 alternative flow
- FR-EVM-06 หากข้อมูลไม่ครบ ระบบต้องแจ้งผู้จัดงานและไม่บันทึก                        <- UC-10 exception flow
- FR-EVM-07 หากสถานที่ไม่พร้อมใช้งาน หรือระบบตรวจสอบสถานที่ไม่สำเร็จ ระบบต้องแจ้งผู้จัดงานและไม่บันทึกอีเว้นต์ด้วยสถานที่นั้น โดยคงข้อมูลที่ผู้จัดงานกรอกไว้ <- UC-10 exception flow
- FR-EVM-08 ข้อมูลอีเว้นต์ที่บันทึกแล้วต้องแสดงต่อผู้ใช้ได้                            <- UC-10 acceptance criteria

## Quality Requirements
- NFR-ACC-01 เฉพาะผู้มีสิทธิ์เท่านั้นที่สร้างและแก้ไขอีเว้นต์ได้ และเมื่อผู้ใช้ที่เข้าสู่ระบบแล้วแต่ไม่มีสิทธิ์จะถูกปฏิเสธพร้อมข้อความทั่วไปว่า "คุณไม่มีสิทธิ์ดำเนินการนี้" โดยไม่ระบุเหตุผลเชิงลึก และบันทึก log ทุกครั้งที่พยายาม
- NFR-DAT-01 ระบบต้องรักษาความถูกต้องของข้อมูลอีเว้นต์ โดยต้องมีการตรวจสอบสถานที่และช่วงเวลาให้ไม่ทับซ้อนกันก่อนบันทึก และต้องไม่บันทึกข้อมูลที่ไม่สมบูรณ์

## Acceptance Criteria
- [ ] AC-EVM-01 (FR-EVM-04)
      Given ผู้จัดงานที่มีสิทธิ์กรอกข้อมูลอีเว้นต์ วัน เวลา และสถานที่ครบถ้วน
      When  กดยืนยันการสร้างอีเว้นต์
      Then  ระบบตรวจสอบและบันทึกอีเว้นต์ใหม่สำเร็จ
- [ ] AC-EVM-02 (FR-EVM-04)
      Given มีอีเว้นต์อยู่ในระบบ
      When  ผู้จัดงานแก้ไขข้อมูลและกดยืนยัน
      Then  ระบบตรวจสอบและบันทึกข้อมูลที่แก้ไขสำเร็จ
- [ ] AC-EVM-03 (FR-EVM-08, NFR-DAT-01)
      Given ผู้จัดงานบันทึกข้อมูลอีเว้นต์แล้ว
      When  ผู้ใช้เปิดดูรายละเอียดอีเว้นต์
      Then  แสดงข้อมูลตามที่บันทึกไว้
- [ ] AC-EVM-04 (FR-EVM-05)
      Given ผู้จัดงานกำลังสร้างหรือแก้ไขอีเว้นต์
      When  เลือกยกเลิกก่อนบันทึก
      Then  ข้อมูลไม่ถูกบันทึกและข้อมูลเดิมไม่เปลี่ยนแปลง
- [ ] AC-EVM-05 (FR-EVM-06)
      Given ผู้จัดงานกรอกข้อมูลไม่ครบ
      When  กดยืนยัน
      Then  ระบบแจ้งให้กรอกข้อมูลให้ครบ และไม่บันทึก
- [ ] AC-EVM-06 (FR-EVM-07)
      Given สถานที่ที่เลือกไม่พร้อมใช้งาน หรือระบบตรวจสอบสถานที่ไม่สำเร็จ
      When  กดยืนยัน
      Then  ระบบแจ้งว่า "สถานที่ไม่พร้อมใช้งาน" หรือ "ตรวจสอบสถานที่ไม่สำเร็จ" ตามสภาวะ และไม่บันทึกอีเว้นต์ พร้อมคงข้อมูลที่กรอกไว้
- [ ] AC-EVM-07 (NFR-ACC-01)
      Given ผู้ใช้ที่เข้าสู่ระบบแล้วแต่ไม่มีสิทธิ์จัดการอีเว้นต์
      When  พยายามสร้างหรือแก้ไขอีเว้นต์
      Then  ระบบปฏิเสธด้วยข้อความ "คุณไม่มีสิทธิ์ดำเนินการนี้" และบันทึก log การพยายามทุกครั้ง

## Assumptions & Open Questions
- ASM-01 พฤติกรรมเมื่อเกิด exception (แจ้งผู้จัดงาน ไม่บันทึก) เป็นข้อสันนิษฐานของผู้เขียน spec
- ASM-02 การตรวจสอบความพร้อมใช้งานของสถานที่ใช้ข้อมูลสถานที่จากฐานข้อมูลของระบบที่ Admin จัดการผ่าน UC-15 โดยผู้จัดงานเลือกสถานที่จากรายการเท่านั้น และสถานที่ที่ถือว่า "พร้อมใช้งาน" คือ (1) อยู่ในรายการและสถานะเปิดใช้งาน และ (2) ไม่มีอีเว้นต์อื่นใช้สถานที่เดียวกันในช่วงวันเวลาที่ทับกัน
- ASM-03 หากระบบไม่สามารถตรวจสอบสถานที่ได้ เช่น ฐานข้อมูลขัดข้อง ระบบจะไม่บันทึกอีเว้นต์ และแจ้งผู้จัดงานว่า "ตรวจสอบสถานที่ไม่สำเร็จ" พร้อมให้ลองใหม่ โดยคงข้อมูลที่ผู้จัดงานกรอกไว้ การตรวจสอบสถานที่และการบันทึกอีเว้นต์ทำในขั้นตอนเดียวกันเพื่อป้องกันการจองซ้อนพร้อมกัน
- ASM-04 การเปิด/ปิดรับลงทะเบียนเข้าชมและเปิดรับสมัครวง รวมถึงจำนวนที่นั่งเป็นข้อมูลของอีเว้นต์ที่ผู้จัดงานตั้งค่าใน UC-10 เท่านั้น UC-04 และ UC-06 อ่านค่ามาตรวจสอบและไม่สามารถแก้ไขได้จาก UC-10
- ASM-05 สวิตช์เปิด/ปิดรับลงทะเบียนเข้าชมและสวิตช์เปิด/ปิดรับสมัครวงเป็นแยกกัน 2 ตัว ค่าเริ่มต้นของทั้งสองคือปิด จำนวนที่นั่งใช้กับการลงทะเบียนเข้าชมเท่านั้น และจำนวนที่นั่งต้องเป็นจำนวนเต็มตั้งแต่ 1 และห้ามต่ำกว่าจำนวนผู้ลงทะเบียนที่ยังไม่ยกเลิก การปิดรับไม่กระทบผู้ที่ลงทะเบียนหรือสมัครไปแล้ว
- ASM-06 เมื่อผู้ใช้ที่เข้าสู่ระบบแล้วแต่ไม่มีสิทธิ์พยายามสร้างหรือแก้ไขอีเว้นต์ ระบบปฏิเสธและแจ้งข้อความเดียวกันว่า "คุณไม่มีสิทธิ์ดำเนินการนี้" โดยไม่ระบุเหตุผลเชิงลึก ไม่ว่าอีเว้นต์นั้นมีอยู่หรือไม่ และข้อมูลไม่เปลี่ยนแปลง นอกจากนี้ระบบบันทึก log ทุกครั้งที่พยายาม ได้แก่ รหัสผู้ใช้ เวลา การกระทำที่พยายาม (สร้าง/แก้ไข) อีเว้นต์เป้าหมาย และผล (ปฏิเสธ) โดยไม่เก็บเนื้อหาที่กรอก ผู้ที่ยังไม่ได้เข้าสู่ระบบจะถูกพาไปหน้าเข้าสู่ระบบ และการตรวจสิทธิ์ทำฝั่งระบบเสมอ ไม่พึ่งการซ่อนเมนูอย่างเดียว
