# แผนงาน: จัดการข้อมูลวงดนตรี (Band Profile Management)

## 1. สรุปแนวทาง
- ระบบจะให้วงที่เข้าสู่ระบบแล้วเข้าถึงเมนูจัดการข้อมูลวงและโหลดข้อมูลวงปัจจุบันเพื่อแสดงบนหน้าแก้ไขข้อมูล
- การแก้ไขข้อมูลวงจะถูกจำกัดให้เฉพาะเจ้าของบัญชีของวงนั้นเท่านั้น ตาม FR-BND-02 และ FR-BND-07
- เมื่อผู้ใช้กดบันทึก ระบบจะตรวจสอบข้อมูลก่อนบันทึกตามเงื่อนไขความถูกต้องใน NFR-DAT-01
- หากข้อมูลไม่ผ่านเงื่อนไข ระบบจะแสดงข้อความที่ระบุผิดที่ช่องใด และไม่บันทึกข้อมูลใหม่
- หากเกิดความล้มเหลวในการบันทึก ระบบจะแสดงข้อความ "บันทึกไม่สำเร็จ" และคงข้อมูลเดิมไว้ตาม FR-BND-06
- ผู้จัดงานมีสิทธิ์ดูข้อมูลวงแบบ read-only เพื่อใช้ในการตรวจสอบใบสมัคร แต่ไม่ได้แก้ไขเนื้อหาข้อมูลวงตาม ASM-02
- ผู้ดูแลระบบสามารถจัดการบัญชีของวง เช่น ระงับบัญชี แต่ไม่แก้ไขเนื้อหาข้อมูลวงแทน ตาม ASM-02

## 2. เทคโนโลยีที่ใช้

| สิ่งที่เลือก | มาจาก | หมายเหตุ |
|---|---|---|
| React (Vite) | ทีมเลือกเอง ไม่ได้มาจาก spec | ใช้สร้างหน้าแสดงข้อมูลวงและฟอร์มแก้ไขข้อมูล |
| Python FastAPI | ทีมเลือกเอง ไม่ได้มาจาก spec | ใช้รับคำขอ โหลดข้อมูลวง และบันทึกข้อมูลวงหลังตรวจสอบ |
| ฐานข้อมูลเชิงสัมพันธ์ | ทีมเลือกเอง ไม่ได้มาจาก spec | ใช้เก็บข้อมูลวงและตรวจสอบความซ้ำของชื่อวง/สมาชิก |

## 3. โมเดลข้อมูล

| Entity | ฟิลด์หลัก | รองรับ |
|---|---|---|
| BandProfile | `band_id`, `user_id`, `band_name`, `genre`, `members`, `contact_name`, `contact_phone`, `links`, `description`, `updated_at` | FR-BND-01, FR-BND-02, FR-BND-03, NFR-DAT-01 |
| BandMember | `member_id`, `band_id`, `member_name`, `member_role` | NFR-DAT-01 |
| BandOwnership | `user_id`, `band_id`, `owner_role` | FR-BND-07, NFR-ACC-01 |
| ValidationError | `field_name`, `message`, `error_code` | FR-BND-05, NFR-DAT-01 |
| SaveResult | `status`, `message`, `previous_data_kept` | FR-BND-06 |

หมายเหตุ:
- ชื่อวงต้องไม่ซ้ำกับวงอื่น และสมาชิกในวงเดียวกันต้องไม่ซ้ำ ตาม NFR-DAT-01
- ความยาวสูงสุดของแต่ละช่องจะถูกกำหนดภายหลังโดยทีมพัฒนา ตาม ASM-04
- ความจริงของข้อมูล เช่น สมาชิกมีตัวตนจริง ไม่ใช่เรื่องที่ระบบตรวจ แต่ให้ผู้จัดงานตรวจใน UC-09 ตาม ASM-04

## 4. API / หน้าจอ

| รายการ | Input / Output หลัก | รองรับ |
|---|---|---|
| `GET /bands/me/profile` | Output: ข้อมูลวงปัจจุบันพร้อมข้อมูลที่สามารถแก้ไขได้ | FR-BND-01 |
| `POST /bands/me/profile/validate` | Input: ข้อมูลวงที่แก้ไข; Output: ผลตรวจความถูกต้องแบบ field-by-field | FR-BND-03, FR-BND-05, NFR-DAT-01 |
| `PUT /bands/me/profile` | Input: ข้อมูลวงที่แก้ไข; Output: บันทึกสำเร็จ/ไม่สำเร็จ | FR-BND-02, FR-BND-03, FR-BND-06 |
| `POST /bands/me/profile/cancel` | Input: session หรือ draft state; Output: คืนค่าเป็นข้อมูลเดิม | FR-BND-04 |
| หน้าแสดงข้อมูลวง | แสดงข้อมูลเดิมพร้อมฟอร์มแก้ไข | FR-BND-01, FR-BND-02 |
| หน้าแจ้งข้อผิดพลาด | แสดงข้อความผิดที่ช่องใด และไม่ล้างข้อมูลที่กรอก | FR-BND-05, NFR-DAT-01 |
| หน้าผลบันทึก | แสดงบันทึกสำเร็จ / บันทึกไม่สำเร็จ | FR-BND-03, FR-BND-06 |
| หน้าปฏิเสธการแก้ไข | ปฏิเสธเมื่อผู้ใช้ไม่ใช่เจ้าของหรือพยายามแก้ไขวงอื่น | FR-BND-07, AC-BND-06 |

## 6. แผนทดสอบจาก Acceptance Criteria

| AC ID | ชื่อ test | ทดสอบอย่างไร |
|---|---|---|
| AC-BND-01 | `test_AC_BND_01_owner_can_update_own_band_profile` | ลงชื่อเข้าใช้งานด้วยเจ้าของบัญชีวง และแก้ไขข้อมูลของวงตนเอง ตรวจว่าการบันทึกสำเร็จ |
| AC-BND-02 | `test_AC_BND_02_valid_data_is_saved_and_visible_after_reload` | ส่งข้อมูลที่ผ่านเงื่อนไขความถูกต้องแล้ว ตรวจว่าข้อมูลใหม่ถูกบันทึกและแสดงผลเมื่อเปิดหน้าอีกครั้ง |
| AC-BND-03 | `test_AC_BND_03_cancel_restores_original_values` | เริ่มแก้ไขข้อมูลแล้วกดยกเลิก ตรวจว่าไม่เปลี่ยนข้อมูลเดิม |
| AC-BND-04 | `test_AC_BND_04_invalid_input_is_rejected_without_saving` | ส่งข้อมูลที่ไม่มีค่า/รูปแบบผิด/ชื่อซ้ำ/สมาชิกซ้ำ ตรวจว่าแสดง error และไม่บันทึก |
| AC-BND-05 | `test_AC_BND_05_save_failure_keeps_original_data` | จำลอง save failure ตรวจว่าระบบแจ้ง "บันทึกไม่สำเร็จ" และข้อมูลเดิมยังคงอยู่ |
| AC-BND-06 | `test_AC_BND_06_non_owner_cannot_edit_other_band` | ลอง login ด้วยบัญชีวงอื่นหรือผู้ใช้ที่ไม่มีสิทธิ์ ตรวจว่าระบบปฏิเสธและไม่เปลี่ยนข้อมูลวงอื่น |

## 7. ลำดับงาน

1. สร้างหน้าแสดงข้อมูลวงและฟอร์มแก้ไขข้อมูลพร้อมโหลดข้อมูลปัจจุบัน (FR-BND-01)
2. เพิ่มการตรวจสิทธิ์ก่อนเปิดหน้าแก้ไขและก่อนบันทึกข้อมูลวง (FR-BND-07, NFR-ACC-01, PRE-BND-01)
3. สร้าง validation ฝั่งเซิร์ฟเวอร์สำหรับข้อมูลบังคับ รูปแบบข้อมูล ชื่อวงซ้ำ และสมาชิกซ้ำ (NFR-DAT-01)
4. สร้างการแสดงข้อผิดพลาดแบบ field-level โดยไม่ล้างข้อมูลที่กรอกก่อนหน้า (FR-BND-05)
5. สร้าง logic สำหรับยกเลิกการแก้ไขและคืนค่าเป็นข้อมูลเดิม (FR-BND-04)
6. สร้างการบันทึกข้อมูลใหม่เมื่อข้อมูลผ่านตรวจ และการปฏิเสธเมื่อบันทึกล้มเหลว (FR-BND-03, FR-BND-06)
7. ทดสอบ end-to-end ตาม AC-BND-01 ถึง AC-BND-06
8. ตรวจความสอดคล้องกับ spec และพร้อมสำหรับ review ก่อนเข้าสู่ขั้นต่อไป

## 8. สิ่งที่ยังไม่ทำ
- Q-03 ยังไม่ตอบชัดเจนว่า วงเริ่มต้นสร้างข้อมูลที่ UC-01 หรือ UC-07 จึงยังไม่กำหนดรายละเอียดของข้อมูลเริ่มต้น/ข้อมูลเริ่มต้นภายในฐานข้อมูลซ้ำกับ UC-01
- ความยาวสูงสุดของแต่ละช่องยังไม่ถูกกำหนดตัวเลขใน spec จึงจะถูกจัดเตรียมภายหลังโดยทีมพัฒนา ตาม ASM-04
- หากทีมต้องการใช้ข้อมูลเริ่มต้นของวงจาก UC-01 เป็นข้อมูลที่มีอยู่ก่อนแสดงหน้า UC-07 จะต้องมีการยืนยันอีกครั้งก่อนเข้ารหัส/ออกแบบ schema แบบสุดท้าย
