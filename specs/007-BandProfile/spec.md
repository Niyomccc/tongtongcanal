# Feature: จัดการข้อมูลวงดนตรี (Band Profile Management)
Spec ID: SPEC-BND-001 | Source: Use Case Specification UC-07 | Use case: UC-07
Owner: TBD | Status: Draft v2 | Updated: 2569-09-20

## Goal
วงดนตรีนักศึกษาแก้ไขและเพิ่มเติมข้อมูลของวงที่มีอยู่แล้วให้เป็นปัจจุบันและถูกต้อง
โดยเฉพาะเจ้าของบัญชีวง (1 บัญชีต่อ 1 วง) เท่านั้นที่แก้ไขข้อมูลของวงตนเองได้
ผู้จัดงานสามารถดูข้อมูลวงเพื่อพิจารณาใบสมัครได้ แต่ไม่แก้ไขข้อมูลวง
ผู้ดูแลระบบสามารถจัดการบัญชีของวง (เช่น ระงับ) ได้ แต่ไม่แก้ไขเนื้อหาข้อมูลวงแทน
การพยายามแก้ไขข้อมูลวงอื่นต้องถูกปฏิเสธ

## Scope
### In scope
- เปิดดูข้อมูลวงเดิม แก้ไข ตรวจสอบ และบันทึกข้อมูลวง
- ยกเลิกการแก้ไขก่อนบันทึก
- ควบคุมสิทธิ์ในการแก้ไขข้อมูลวง
### Out of scope
- สมัครเข้าร่วมแสดง (UC-06) | ตรวจสอบและอนุมัติวงดนตรี (UC-09) | จัดการบัญชีผู้ใช้ (UC-14)

## Constraints
- PRE-BND-01 วงเข้าสู่ระบบแล้ว (precondition)

## Requirements
- FR-BND-01 ระบบต้องแสดงข้อมูลเดิมของวงเมื่อวงเลือกเมนูจัดการข้อมูลวง                 <- UC-07 main flow ขั้น 1-2
- FR-BND-02 ระบบต้องให้เจ้าของบัญชีของวงนั้นเพิ่มหรือแก้ไขข้อมูลของวงตนเองและกดบันทึกได้   <- UC-07 main flow ขั้น 3-4
- FR-BND-03 เมื่อเจ้าของบัญชีวงกดบันทึก ระบบต้องตรวจสอบข้อมูลตามเงื่อนไขความถูกต้อง
  และบันทึกข้อมูลใหม่เมื่อข้อมูลผ่านเงื่อนไข                                            <- UC-07 main flow ขั้น 5-6
- FR-BND-04 ระบบต้องให้วงยกเลิกการแก้ไขได้ โดยข้อมูลเดิมไม่เปลี่ยนแปลง                 <- UC-07 alternative flow
- FR-BND-05 หากข้อมูลไม่ถูกต้อง ระบบต้องแจ้งผู้ใช้และไม่บันทึกข้อมูล                     <- UC-07 exception flow
- FR-BND-06 หากระบบไม่สามารถบันทึกได้ ระบบต้องแจ้งผู้ใช้ว่าบันทึกไม่สำเร็จ
  และคงข้อมูลเดิมไว้                                                              <- UC-07 exception flow
- FR-BND-07 ระบบต้องอนุญาตให้เฉพาะเจ้าของบัญชีวงนั้นเท่านั้นที่แก้ไขข้อมูลของวงตนเอง
  ผู้จัดงานสามารถดูข้อมูลวงเพื่อการตรวจสอบใบสมัครได้ แต่ไม่แก้ไขข้อมูลวง
  ผู้ดูแลระบบสามารถจัดการบัญชีของวง (เช่น ระงับ) ได้ แต่ไม่แก้ไขเนื้อหาข้อมูลวงแทน
  การพยายามแก้ไขข้อมูลวงอื่นต้องถูกปฏิเสธ                                            <- UC-07 NFR / acceptance criteria

## Quality Requirements
- NFR-DAT-01 ข้อมูลวงที่บันทึกต้องมีความถูกต้อง โดยระบบต้องตรวจสอบฝั่งเซิร์ฟเวอร์ก่อนบันทึกว่า
  (1) ฟิลด์บังคับครบ ได้แก่ ชื่อวง แนวเพลง สมาชิกอย่างน้อย 1 คน ผู้ติดต่อ (ชื่อและเบอร์โทร)
  และช่องที่มีแต่ช่องว่างถือว่าไม่กรอก
  (2) รูปแบบข้อมูลถูกต้อง เช่น เบอร์โทรตามรูปแบบเบอร์ไทย และลิงก์ผลงานเป็น URL
  (3) ชื่อวงไม่ซ้ำกับวงอื่น
  (4) สมาชิกในวงเดียวกันไม่ซ้ำ
  ระบบต้องแจ้งว่าผิดที่ช่องใดโดยไม่ล้างข้อมูลที่กรอก และไม่ตรวจความจริงของข้อมูล เช่น สมาชิกมีตัวตนจริง
  ให้ผู้จัดงานตรวจใน UC-09
- NFR-ACC-01 ต้องมีการควบคุมสิทธิ์ในการแก้ไขข้อมูลวง

## Acceptance Criteria
- [ ] AC-BND-01 (FR-BND-02)
      Given วงเข้าสู่ระบบแล้ว และเปิดข้อมูลวง
      When  แก้ไขข้อมูลของวงตนเองและกดบันทึก
      Then  วงแก้ไขข้อมูลได้สำเร็จ
- [ ] AC-BND-02 (FR-BND-03, NFR-DAT-01)
      Given วงแก้ไขข้อมูลที่ผ่านเงื่อนไขความถูกต้อง
      When  กดบันทึก
      Then  ระบบบันทึกข้อมูลใหม่ และเมื่อเปิดดูอีกครั้งจะแสดงข้อมูลที่บันทึกล่าสุด
- [ ] AC-BND-03 (FR-BND-04)
      Given วงกำลังแก้ไขข้อมูลและยังไม่กดบันทึก
      When  เลือกยกเลิก
      Then  ข้อมูลวงเดิมไม่เปลี่ยนแปลง
- [ ] AC-BND-04 (FR-BND-05)
      Given วงกรอกข้อมูลไม่ถูกต้อง
      When  กดบันทึก
      Then  ระบบแจ้งผู้ใช้ว่าข้อมูลผิดที่ช่องใด และไม่บันทึกข้อมูล
- [ ] AC-BND-05 (FR-BND-06)
      Given ระบบไม่สามารถบันทึกได้
      When  วงกดบันทึก
      Then  ระบบแจ้งว่าบันทึกไม่สำเร็จ และข้อมูลเดิมยังคงอยู่
- [ ] AC-BND-06 (FR-BND-07, NFR-ACC-01)
      Given ผู้ใช้ไม่ใช่เจ้าของบัญชีของวงนั้น หรือพยายามแก้ไขข้อมูลวงอื่น
      When  พยายามแก้ไขข้อมูลวง
      Then  ระบบไม่อนุญาต และข้อมูลวงไม่เปลี่ยนแปลง

## Assumptions & Open Questions
- ASM-01 พฤติกรรมเมื่อเกิด exception (แจ้งผู้ใช้ คงข้อมูลเดิม) เป็นข้อสันนิษฐานของผู้เขียน spec
- ASM-02 เจ้าของบัญชีวงคือผู้มีสิทธิ์แก้ไขข้อมูลของวงตนเองเท่านั้น ผู้จัดงานสามารถดูข้อมูลวงแบบ read-only เพื่อจัดการใบสมัคร แต่ไม่แก้ไขเนื้อหาข้อมูลวง ผู้ดูแลระบบสามารถจัดการบัญชีของวง เช่น ระงับบัญชี แต่ไม่แก้ไขหรือแทนที่ข้อมูลวงเอง การพยายามแก้ไขข้อมูลวงอื่นต้องถูกปฏิเสธ
- ASM-03 UC-07 เป็นการแก้ไขและเพิ่มเติมข้อมูลของวงที่มีอยู่แล้วเท่านั้น ไม่สร้างวงใหม่ วงถูกสร้างพร้อมบัญชีตอนสมัครสมาชิกใน UC-01 (1 บัญชีต่อ 1 วง) และคำว่า "เพิ่ม" ใน UC-07 หมายถึงการเพิ่มข้อมูลลงในโปรไฟล์ เช่น สมาชิกหรือแนวเพลงที่ยังไม่ได้กรอกตอนสมัคร ไม่ได้หมายถึงการเพิ่มวงเข้าระบบ
- ASM-04 "ข้อมูลถูกต้อง" หมายถึงผ่านการตรวจโดยระบบ 4 อย่าง คือ (1) ฟิลด์บังคับครบ (2) รูปแบบข้อมูลถูกต้อง (3) ชื่อวงไม่ซ้ำกับวงอื่น (4) สมาชิกในวงเดียวกันไม่ซ้ำ ระบบตรวจฝั่งเซิร์ฟเวอร์ทุกครั้งก่อนบันทึก และเมื่อไม่ผ่านต้องบอกว่าผิดที่ช่องใดโดยไม่ล้างข้อมูลที่กรอก ความจริงของข้อมูล เช่น สมาชิกมีตัวตนจริง ระบบไม่ตรวจ ให้ผู้จัดงานตรวจใน UC-09 ความยาวสูงสุดของแต่ละช่องตามที่ทีมพัฒนากำหนด
- Q-03 Use Case ระบุ "เพิ่ม" ข้อมูลวง แต่ Precondition ให้วงเข้าสู่ระบบแล้ว ข้อมูลวงเริ่มต้นสร้างที่ขั้นตอนสมัครสมาชิก (UC-01) หรือที่ UC-07?
