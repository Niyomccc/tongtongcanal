# Feature: จัดตารางการแสดง (Schedule Management)
Spec ID: SPEC-SCM-001 | Source: Use Case Specification UC-11 | Use case: UC-11
Owner: TBD | Status: Draft v1 | Updated: 2569-09-20

## Goal
ผู้จัดงานกำหนดลำดับ วัน เวลา และสถานที่แสดงของแต่ละวงที่ได้รับอนุมัติโดยไม่เกิดเวลาซ้ำซ้อน
แล้วบันทึกตารางเป็น Draft เพื่อให้สามารถตรวจสอบความถูกต้องก่อนเผยแพร่
เพื่อให้วงและผู้ชมทราบกำหนดการเมื่อผู้จัดงานกดเผยแพร่

## Scope
### In scope
- แสดงวงที่ได้รับอนุมัติ และกำหนดวัน เวลา สถานที่ของแต่ละวง
- ตรวจสอบเวลาซ้ำ บันทึกและเผยแพร่ตาราง
### Out of scope
- ตรวจสอบและอนุมัติวงดนตรี (UC-09) | ดูตารางการแสดง (UC-03) | สร้าง / แก้ไขอีเว้นต์ (UC-10)

## Constraints
- PRE-SCM-01 มีอีเว้นต์และวงที่ได้รับอนุมัติแล้ว (precondition)
- CON-ACC-01 เฉพาะผู้จัดงานที่ได้รับสิทธิ์เท่านั้นที่จัดตารางได้

## Requirements
- FR-SCM-01 ระบบต้องแสดงรายชื่อวงที่ได้รับอนุมัติให้ผู้จัดงานเลือก                       <- UC-11 main flow ขั้น 1-2
- FR-SCM-02 ระบบต้องให้ผู้จัดงานกำหนดวัน เริ่มเวลา สถานที่ และลำดับ (order) ของวงที่เลือก โดยลำดับเป็นฟิลด์แยกจากวันและเวลาที่ผู้จัดงานกำหนด/ปรับได้เอง <- UC-11 main flow ขั้น 3-4
- FR-SCM-03 ระบบต้องตรวจสอบ Time Conflict และ Venue Conflict อย่างอิสระต่อกันก่อนบันทึก และแจ้งทั้งสองรายการพร้อมกันในคำตอบเดียวหากมีปัญหา <- UC-11 main flow ขั้น 5
- FR-SCM-04 เมื่อผู้จัดงานยืนยัน ระบบต้องบันทึกตารางเป็นสถานะ Draft และไม่เผยแพร่ให้ผู้ชมและวงเห็นทันที จนกว่าผู้จัดงานจะกดปุ่มเผยแพร่แยกอีกขั้นตอนหนึ่ง <- UC-11 main flow ขั้น 6-7
- FR-SCM-05 หากมี Time Conflict ระบบต้องแจ้งผู้จัดงานและให้เลือกเวลาใหม่ โดยไม่บันทึกตารางที่มี Time Conflict <- UC-11 alternative flow
- FR-SCM-06 หากมี Venue Conflict ระบบต้องแจ้งผู้จัดงานและไม่บันทึกตารางด้วยสถานที่นั้น <- UC-11 exception flow
- FR-SCM-07 หากระบบไม่สามารถบันทึกตารางได้ ระบบต้องแจ้งผู้จัดงานว่าบันทึกไม่สำเร็จ <- UC-11 exception flow

## Quality Requirements
- NFR-DAT-01 ระบบต้องป้องกันข้อมูลเวลาซ้ำ ไม่ให้มีตารางที่เวลาซ้ำกันถูกบันทึก
- NFR-PERF-01 ระบบต้องแสดงตารางได้อย่างรวดเร็ว [ค่าที่วัดได้: ต้องกำหนด, Q-03]

## Acceptance Criteria
- [ ] AC-SCM-01 (FR-SCM-02, FR-SCM-04)
      Given มีอีเว้นต์และวงที่ได้รับอนุมัติแล้ว
      When  ผู้จัดงานกำหนดวัน เริ่มเวลา สถานที่ และลำดับของวง แล้วยืนยัน
      Then  ระบบบันทึกตารางในสถานะ Draft สำเร็จ และยังไม่เผยแพร่ถึงผู้ชมและวง
- [ ] AC-SCM-02 (FR-SCM-03, FR-SCM-05, NFR-DAT-01)
      Given มีวงหนึ่งถูกจัดเวลาแสดงไว้แล้ว
      When  ผู้จัดงานกำหนดเวลาให้อีกวงซ้ำกับเวลานั้น
      Then  ระบบไม่อนุญาต แจ้ง Time Conflict และให้เลือกเวลาใหม่
- [ ] AC-SCM-03 (FR-SCM-03, FR-SCM-06)
      Given มีสถานที่ที่เลือกไม่ว่างในช่วงเวลานั้น
      When  ผู้จัดงานยืนยัน
      Then  ระบบแจ้ง Venue Conflict พร้อมกับ Time Conflict ที่เกิดขึ้น (ถ้ามี) และไม่บันทึกตาราง
- [ ] AC-SCM-04 (FR-SCM-04)
      Given ผู้จัดงานบันทึกตารางเป็น Draft แล้ว
      When  ผู้ชมหรือวงเปิดดูตารางการแสดง
      Then  ยังไม่เห็นตารางที่บันทึกไว้จนกว่าจะกดเผยแพร่แยก
- [ ] AC-SCM-05 (FR-SCM-07)
      Given ระบบไม่สามารถบันทึกตารางได้
      When  ผู้จัดงานยืนยัน
      Then  ระบบแจ้งว่าบันทึกไม่สำเร็จ และไม่มีการเผยแพร่ตาราง
- [ ] AC-SCM-06 (CON-ACC-01)
      Given ผู้ใช้ไม่ใช่ผู้จัดงานที่ได้รับสิทธิ์
      When  พยายามจัดตารางการแสดง
      Then  ระบบไม่อนุญาต

## Assumptions & Open Questions
- ASM-01 พฤติกรรมเมื่อเกิด exception (แจ้งผู้จัดงาน ไม่บันทึก) เป็นข้อสันนิษฐานของผู้เขียน spec
- ASM-02 ระบบตรวจสอบ Time Conflict และ Venue Conflict อย่างอิสระต่อกัน แล้วแจ้ง error ทั้งสองรายการพร้อมกันในคำตอบเดียว หากมีปัญหา โดยไม่ใช้ fail-fast ที่หยุดหลัง error แรก
- ASM-03 ตารางมีสถานะ Draft และ Published แยกกัน โดยบันทึกเป็น Draft ก่อน และต้องกดปุ่ม “เผยแพร่” เป็นขั้นตอนแยกต่างหากเพื่อให้ผู้จัดงานตรวจสอบก่อนเปิดให้สาธารณะเห็น
- ASM-04 ลำดับ (order/sequence) เป็นฟิลด์แยกจากวันและเวลา โดยผู้จัดงานกำหนดหรือปรับได้เองในแต่ละวง และวัน-เวลาใช้เพื่อกำหนดเวลาเริ่มเท่านั้น ไม่ใช่ตัวตัดสินลำดับเสมอไป
- Q-01 "เวลาซ้ำ" ตรวจที่เงื่อนไจใด: สถานที่เดียวกันเวลาทับกัน วงเดียวกันเวลาทับกัน หรือทั้งสองอย่าง?
