# Feature: ตรวจสอบสถานะการสมัคร (Application Status)
Spec ID: SPEC-STS-001 | Source: Use Case Specification UC-08 | Use case: UC-08
Owner: TBD | Status: Draft v2 | Updated: 2569-09-20

## Goal
วงดนตรีนักศึกษาตรวจสอบสถานะใบสมัครของตนเองแบบหลายใบสมัคร เพื่อทราบผลการสมัครและข้อความจากผู้จัดงาน โดยสถานะที่ใช้มี 4 ค่า คือ รอตรวจสอบ / ส่งกลับแก้ไข / อนุมัติ / ปฏิเสธ

## Scope
### In scope
- แสดงรายการใบสมัครทั้งหมดของวงที่เข้าสู่ระบบ พร้อมสถานะและข้อความจากผู้จัดงาน
- กดเข้าดูรายละเอียดใบสมัครแต่ละรายการได้
- ให้วงเห็นเฉพาะข้อมูลของตนเอง
### Out of scope
- สมัครเข้าร่วมแสดง (UC-06) | ตรวจสอบและอนุมัติวงดนตรี (UC-09)

## Constraints
- PRE-STS-01 วงเคยส่งใบสมัครเข้าร่วมงาน (precondition)

## Requirements
- FR-STS-01 ระบบต้องให้วงเลือกเมนูสถานะการสมัคร และแสดงรายการใบสมัครทั้งหมดของวงที่ล็อกอิน เรียงตามสถานะ "ส่งกลับแก้ไข" ก่อน แล้วตามด้วย "รอตรวจสอบ" "อนุมัติ" และ "ปฏิเสธ" ภายในสถานะเดียวกันเรียงตามวันที่ส่งล่าสุดก่อน <- UC-08 main flow ขั้น 1-2
- FR-STS-02 ระบบต้องตรวจสอบสถานะของแต่ละใบสมัครและแสดงผล ได้แก่ รอตรวจสอบ / ส่งกลับแก้ไข / อนุมัติ / ปฏิเสธ พร้อมชื่ออีเว้นต์ สถานะ วันที่ส่ง และข้อความจากผู้จัดงาน (ถ้ามี) <- UC-08 main flow ขั้น 3-4
- FR-STS-03 หากใบสมัครยังอยู่ระหว่างการพิจารณา หรือถูกส่งกลับให้แก้ไข ระบบต้องแสดงสถานะที่ตรงกับสถานะปัจจุบัน ได้แก่ "รอตรวจสอบ" หรือ "ส่งกลับแก้ไข" <- UC-08 alternative flow
- FR-STS-04 หากไม่พบใบสมัครของวง ระบบต้องแจ้งว่าไม่พบใบสมัคร <- UC-08 exception flow
- FR-STS-05 ระบบต้องแสดงเฉพาะใบสมัครของวงที่เข้าสู่ระบบ และเมื่อกดเข้าไปที่รายการใด ให้สามารถเปิดดูรายละเอียดใบสมัครนั้นได้ <- UC-08 NFR

## Quality Requirements
- NFR-ACC-01 ผู้ใช้ต้องเห็นเฉพาะข้อมูลของตนเอง
- NFR-DAT-01 ระบบต้องแสดงสถานะอย่างถูกต้องตรงกับผลที่ผู้จัดงานบันทึก

## Acceptance Criteria
- [ ] AC-STS-01 (FR-STS-02, NFR-DAT-01)
      Given วงมีใบสมัครที่ผู้จัดงานอนุมัติแล้ว
      When  วงเปิดสถานะการสมัคร
      Then  แสดงสถานะ "อนุมัติ"
- [ ] AC-STS-02 (FR-STS-02, NFR-DAT-01)
      Given วงมีใบสมัครที่ผู้จัดงานปฏิเสธแล้ว
      When  วงเปิดสถานะการสมัคร
      Then  แสดงสถานะ "ปฏิเสธ" และข้อความจากผู้จัดงานที่ระบุเหตุผลปฏิเสธ
- [ ] AC-STS-03 (FR-STS-03)
      Given ใบสมัครของวงอยู่ระหว่างการพิจารณา หรือถูกส่งกลับให้แก้ไข
      When  วงเปิดสถานะการสมัคร
      Then  แสดงสถานะที่ตรงกับสถานะปัจจุบัน และแสดงข้อความจากผู้จัดงาน (ถ้ามี)
- [ ] AC-STS-04 (FR-STS-04)
      Given วงไม่มีใบสมัครในระบบ
      When  วงเปิดสถานะการสมัคร
      Then  ระบบแจ้งว่าไม่พบใบสมัคร
- [ ] AC-STS-05 (FR-STS-05, NFR-ACC-01)
      Given มีใบสมัครของวงอื่นอยู่ในระบบ
      When  วงเปิดสถานะการสมัคร
      Then  แสดงเฉพาะรายการใบสมัครของวงที่เข้าสู่ระบบ ไม่แสดงของวงอื่น และเรียงตามลำดับที่กำหนด

## Assumptions & Open Questions
- ASM-01 พฤติกรรมเมื่อไม่พบใบสมัคร (แจ้งข้อความให้ผู้ใช้ทราบ) เป็นข้อสันนิษฐานของผู้เขียน spec
- ASM-02 เมื่อวงมีหลายใบสมัคร ระบบจะแสดงรายการใบสมัครทั้งหมดของวงที่ล็อกอิน โดยเรียงตามสถานะ "ส่งกลับแก้ไข" ก่อน แล้วตามด้วย "รอตรวจสอบ" "อนุมัติ" และ "ปฏิเสธ" ภายในสถานะเดียวกันเรียงตามวันที่ส่งล่าสุดก่อน
- ASM-03 ผู้จัดงานใช้ช่อง "ข้อความจากผู้จัดงาน" เดียวกันทั้งกรณีส่งกลับแก้ไขและปฏิเสธ พร้อมข้อความที่ไม่เป็นค่าว่างเมื่อปฏิเสธ ใบสมัครที่ถูกปฏิเสธต้องแสดงข้อความนั้นในหน้าสถานะการสมัครของวงเท่านั้น
- ASM-04 สถานะ "ส่งกลับแก้ไข" เป็นสถานะแยกจาก "รอตรวจสอบ" และเมื่อวงแก้ไขแล้วส่งใหม่ ใบสมัครเดิมกลับเป็น "รอตรวจสอบ" โดยไม่สร้างใบสมัครใหม่
- ASM-05 ผู้จัดงานต้องกรอกเหตุผลทุกครั้งที่ปฏิเสธใบสมัคร และเหตุผลนั้นจะถูกบันทึกไว้ในประวัติการอนุมัติของใบสมัครเดียวกัน
