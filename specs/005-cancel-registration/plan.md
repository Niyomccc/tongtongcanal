## 1. สรุปแนวทาง

1. ตรวจสอบว่าผู้ใช้มีการลงทะเบียนของอีเว้นต์อยู่ในสถานะ "ลงทะเบียน" ตาม PRE-CXL-01
2. แสดงข้อมูลการลงทะเบียนของผู้ใช้ และให้เลือกการลงทะเบียนที่ต้องการยกเลิก (FR-CXL-01)
3. แสดงข้อความขอยืนยันก่อนยกเลิก (FR-CXL-02)
4. หากผู้ใช้ไม่ยืนยัน ให้คงข้อมูลการลงทะเบียนเดิมไว้โดยไม่เปลี่ยนแปลง (FR-CXL-04)
5. หากผู้ใช้ยืนยัน ให้เปลี่ยนสถานะเป็น "ยกเลิก" และปรับปรุงจำนวนผู้ลงทะเบียนของอีเว้นต์ทันทีหลังยกเลิกสำเร็จ (FR-CXL-03, ASM-01, ASM-03)
6. หากไม่พบข้อมูลการลงทะเบียน ให้แจ้งผู้ใช้และไม่เปลี่ยนแปลงข้อมูล (FR-CXL-05)
7. รองรับการลงทะเบียนอีเว้นต์เดิมใหม่หลังรายการเดิมมีสถานะ "ยกเลิก" โดยกฎการลงทะเบียนซ้ำของ UC-04 นับเฉพาะรายการที่ยังไม่ยกเลิก (ASM-04)

การตรวจสิทธิ์ว่า registration เป็นของผู้ใช้ปัจจุบัน การรับประกันการเปลี่ยนสถานะกับจำนวนที่ว่างให้สำเร็จพร้อมกัน รายละเอียดการแสดงจำนวนต่อผู้จัดงาน และฟิลด์ข้อมูลการยกเลิก ยังรอคำตอบ Q-04 ถึง Q-07

## 2. เทคโนโลยีที่ใช้

| สิ่งที่เลือก | มาจาก | หมายเหตุ |
|---|---|---|
| ภาษาและ framework ของส่วนติดต่อผู้ใช้ | ทีมเลือกเอง ไม่ได้มาจาก spec | ใช้แสดงข้อมูลการลงทะเบียน กล่องยืนยัน และผลลัพธ์ |
| ภาษาและ framework ของส่วนประมวลผล | ทีมเลือกเอง ไม่ได้มาจาก spec | ใช้ตรวจสอบสถานะ ประมวลผลการยกเลิก และคำนวณจำนวนผู้ลงทะเบียน |
| ฐานข้อมูลที่รองรับการปรับสถานะและจำนวนผู้ลงทะเบียน | ทีมเลือกเอง ไม่ได้มาจาก spec | ต้องเลือกให้สอดคล้องกับคำตอบ Q-05 เมื่อทีมกำหนดว่าการเปลี่ยนแปลงต้องสำเร็จพร้อมกันหรือไม่ |

## 3. โมเดลข้อมูล

| Entity | ฟิลด์หลัก | รองรับ |
|---|---|---|
| User | `user_id`, ข้อมูลตัวตนของผู้ใช้ที่เข้าสู่ระบบ | PRE-CXL-01, FR-CXL-01, Q-04 |
| Event | `event_id`, จำนวนผู้ลงทะเบียนหรือจำนวนที่ว่าง | FR-CXL-03, AC-CXL-03, ASM-01, ASM-03 |
| Registration | `registration_id`, `user_id`, `event_id`, `status` | FR-CXL-01, FR-CXL-03, FR-CXL-04, FR-CXL-05, ASM-04 |
| Cancellation record | รายละเอียดการยกเลิกตามที่ทีมกำหนด | NFR-DAT-01, Q-07 |

หมายเหตุ: จำนวนผู้ลงทะเบียนต้องนับเฉพาะ Registration ที่มีสถานะยังไม่ยกเลิกตาม ASM-01 และรายการที่มีสถานะ "ยกเลิก" ต้องไม่ขัดขวางการลงทะเบียนอีเว้นต์เดิมใหม่ตาม ASM-04 การกำหนดฟิลด์จริงของ Cancellation record ยังทำไม่ได้จนกว่าจะตอบ Q-07

## 4. API / หน้าจอ

| รายการ | Input / Output หลัก | รองรับ |
|---|---|---|
| ตรวจสอบ session และสิทธิ์เจ้าของรายการ | Input: session ของผู้ใช้; Output: ผู้ใช้ที่อนุญาตให้เข้าถึงรายการของตนเอง | PRE-CXL-01, FR-CXL-01, Q-04 |
| `GET` ข้อมูลการลงทะเบียนของผู้ใช้ | Input: ผู้ใช้ปัจจุบัน; Output: รายการลงทะเบียนที่มีสถานะยกเลิกได้ | FR-CXL-01, PRE-CXL-01 |
| `POST` ขอเริ่มการยกเลิก | Input: `registration_id`; Output: ข้อมูลรายการและผลการตรวจพบข้อมูล | FR-CXL-01, FR-CXL-05, AC-CXL-05, Q-08 |
| หน้าจอยืนยันการยกเลิก | Input: การเลือกยืนยันหรือไม่ยืนยัน; Output: ผลการเลือก | FR-CXL-02, FR-CXL-04, AC-CXL-01, AC-CXL-04 |
| `POST` ยืนยันการยกเลิก | Input: `registration_id`, ผู้ใช้ปัจจุบัน; Output: สถานะยกเลิกและจำนวนที่ปรับปรุง หรือข้อผิดพลาด | FR-CXL-03, NFR-DAT-01, AC-CXL-02, AC-CXL-03, Q-05 |
| หน้าจอผลการยกเลิก | Output: ผลสำเร็จ หรือข้อความไม่พบข้อมูล/ไม่สำเร็จตามที่ทีมกำหนด | FR-CXL-03, FR-CXL-05, AC-CXL-01, AC-CXL-05, Q-08 |

การแสดงจำนวนต่อผู้จัดงานยังไม่กำหนดขอบเขต เพราะอยู่ใน Q-06 และไม่ควรเพิ่มหน้าจอหรือ endpoint แทนทีม

## 5. ตารางตรวจ Constraints และ Assumptions

| ID | ถูกนำไปใช้ที่ไหนใน plan | สถานะ |
|---|---|---|
| PRE-CXL-01 | ตรวจว่าผู้ใช้มี Registration ของอีเว้นต์ในสถานะ "ลงทะเบียน" ก่อนให้ยกเลิก | ใช้แล้ว |
| ASM-01 | นับจำนวนผู้ลงทะเบียนจากรายการที่ยังไม่ยกเลิก และลดจำนวนที่นับได้ 1 รายการเมื่อยกเลิกสำเร็จ | ใช้แล้ว |
| ASM-02 | ไม่สร้าง validation เรื่องเส้นตายในปัจจุบัน; หากมีการกำหนดภายหลัง ต้องใช้รูปแบบ "ก่อนวันงาน [N] วัน" | ใช้แล้ว |
| ASM-03 | ทำให้จำนวนที่ว่างเพิ่มขึ้นและเปิดให้ผู้อื่นลงทะเบียนได้ทันทีหลังการยกเลิกสำเร็จ | ใช้แล้ว |
| ASM-04 | ไม่ถือรายการที่สถานะ "ยกเลิก" เป็นรายการซ้ำในกระบวนการลงทะเบียนของ UC-04 | ใช้แล้ว |
| Q-04 | ยังไม่กำหนดวิธีตรวจเจ้าของ Registration | รอคำตอบ |
| Q-05 | ยังไม่กำหนดพฤติกรรมเมื่อการเปลี่ยนแปลงบางส่วนสำเร็จ | รอคำตอบ |
| Q-06 | ยังไม่กำหนดว่าต้องแสดงจำนวนต่อผู้จัดงานในฟีเจอร์นี้หรือไม่ | รอคำตอบ |
| Q-07 | ยังไม่กำหนดฟิลด์ข้อมูลการยกเลิก | รอคำตอบ |
| Q-08 | ยังไม่กำหนดข้อความและความหมายของกรณีไม่พบข้อมูล/ยกเลิกแล้ว | รอคำตอบ |

## 6. แผนทดสอบจาก Acceptance Criteria

| AC ID | ชื่อ test | ทดสอบอย่างไร |
|---|---|---|
| AC-CXL-01 | `test_AC_CXL_01_cancel_registration_after_confirmation` | เตรียมผู้ใช้ที่มี Registration สถานะ "ลงทะเบียน" เลือกยกเลิกและยืนยัน ตรวจว่าระบบยกเลิกสำเร็จ |
| AC-CXL-02 | `test_AC_CXL_02_change_registration_status_to_cancelled` | ยืนยันการยกเลิก แล้วตรวจว่าสถานะ Registration เปลี่ยนเป็น "ยกเลิก" และข้อมูลที่บันทึกตรงกับข้อกำหนดที่ทีมตอบ Q-07 เมื่อมีคำตอบ |
| AC-CXL-03 | `test_AC_CXL_03_update_event_registration_count` | เตรียมจำนวนผู้ลงทะเบียนเป็น N ยกเลิกสำเร็จ แล้วตรวจว่าจำนวนที่นับเป็นผู้ลงทะเบียนเปลี่ยนเป็น N-1 และจำนวนที่ว่างเพิ่มขึ้นทันที |
| AC-CXL-04 | `test_AC_CXL_04_keep_registration_when_not_confirmed` | เปิดข้อความยืนยัน เลือกไม่ยืนยัน แล้วตรวจว่าสถานะและข้อมูล Registration เดิมไม่เปลี่ยนแปลง |
| AC-CXL-05 | `test_AC_CXL_05_reject_cancellation_when_registration_not_found` | ส่งคำขอยกเลิกกรณีไม่พบ Registration ตรวจข้อความและตรวจว่าไม่มีข้อมูลใดเปลี่ยนแปลง; รายละเอียดกรณีรายการยกเลิกแล้วรอ Q-08 |

การทดสอบสิทธิ์เจ้าของรายการและรายละเอียดข้อมูลการยกเลิกยังสรุปไม่ได้จนกว่าจะตอบ Q-04 และ Q-07 ส่วนการทดสอบความสำเร็จพร้อมกันของการเปลี่ยนสถานะกับจำนวนต้องรอ Q-05

## 7. ลำดับงาน

1. ตรวจ session และค้นหา Registration ของผู้ใช้ที่มีสถานะ "ลงทะเบียน" (PRE-CXL-01, FR-CXL-01)
2. แสดงข้อมูล Registration และตัวเลือกยกเลิก (FR-CXL-01)
3. แสดงข้อความขอยืนยันการยกเลิก (FR-CXL-02)
4. หากผู้ใช้ไม่ยืนยัน ให้จบกระบวนการโดยไม่แก้ข้อมูล (FR-CXL-04, AC-CXL-04)
5. หากผู้ใช้ยืนยัน ให้ตรวจรายการอีกครั้งก่อนเปลี่ยนสถานะ เพื่อไม่ยกเลิกรายการที่ไม่พบหรือไม่อยู่ในสถานะที่ยกเลิกได้ (FR-CXL-03, FR-CXL-05, Q-08)
6. บันทึกสถานะ "ยกเลิก" และปรับปรุงจำนวนผู้ลงทะเบียนที่นับเฉพาะรายการที่ยังไม่ยกเลิก (FR-CXL-03, ASM-01)
7. ทำให้จำนวนที่ว่างเพิ่มขึ้นทันทีและพร้อมให้ UC-04 ใช้ตรวจสอบการลงทะเบียนรายการใหม่ (ASM-03, ASM-04)
8. แสดงผลการยกเลิกสำเร็จ หรือข้อความไม่พบข้อมูล/ข้อผิดพลาดตามที่ทีมกำหนด (AC-CXL-01, AC-CXL-05, Q-08)
9. เขียนและรันทดสอบตาม AC-CXL-01 ถึง AC-CXL-05

## 8. สิ่งที่ยังทำไม่ได้หรือรอคำตอบ

- Q-04 ยังไม่ทราบวิธีตรวจว่าผู้ใช้เป็นเจ้าของ Registration จึงยังสรุป authorization และทดสอบกรณีเข้าถึงรายการของผู้อื่นไม่ได้
- Q-05 ยังไม่ทราบว่าการเปลี่ยนสถานะกับจำนวนผู้ลงทะเบียนต้องสำเร็จพร้อมกันหรือไม่ จึงยังเลือกกลไกจัดการความล้มเหลวและทดสอบ partial update ไม่ได้
- Q-06 ยังไม่ทราบว่าต้องเพิ่มการแสดงจำนวนสำหรับผู้จัดงานในฟีเจอร์นี้หรือไม่ จึงยังไม่กำหนดหน้าจอ/endpoint ของผู้จัดงาน
- Q-07 ยังไม่ทราบฟิลด์ที่ต้องบันทึกเมื่อยกเลิก จึงยังสรุป schema และการตรวจ NFR-DAT-01 ได้ไม่ครบ
- Q-08 ยังไม่ทราบข้อความและการจัดการรายการที่ถูกยกเลิกแล้ว จึงยังสรุปผลลัพธ์ของ FR-CXL-05 ได้ไม่ครบ
