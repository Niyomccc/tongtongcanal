# Feature: จัดการข้อมูลระบบ (System Data Management)
Spec ID: SPEC-SYS-001 | Source: Use Case Specification UC-15 | Use case: UC-15
Owner: TBD | Status: Draft v2 | Updated: 2026-09-20

## Goal
ผู้ดูแลระบบเพิ่ม แก้ไข หรือลบข้อมูลพื้นฐานและข้อมูลที่ใช้ในการทำงานของระบบ
ให้ข้อมูลถูกต้อง สอดคล้องกัน และพร้อมใช้งานสำหรับผู้จัดงาน

## Scope
### In scope
- เลือกข้อมูลที่ต้องการจัดการ และเพิ่ม / แก้ไข / ลบ
- ตรวจสอบข้อมูลก่อนบันทึก และยืนยันก่อนบันทึก
- ควบคุมสิทธิ์ และสำรองข้อมูล
### Out of scope
- จัดการบัญชีผู้ใช้ (UC-14) | สร้าง / แก้ไขอีเว้นต์ (UC-10)

## Constraints
- PRE-SYS-01 ผู้ดูแลระบบเข้าสู่ระบบและมีสิทธิ์ในการจัดการข้อมูล (precondition)

## Requirements
- FR-SYS-01 ระบบต้องแสดง system master/reference data ที่ฟีเจอร์อื่นต้องพึ่งพาให้ผู้ดูแลระบบเลือกจัดการ โดยครอบคลุมอย่างน้อยสถานที่ (venues), ประเภทอีเว้นต์ (event categories/types), ประเภท/บทบาทที่เกี่ยวข้องกับการแสดง เช่น ประเภทวง/ประเภทการแสดง และหมวดหมู่ประกาศ (announcement categories) หากมีการใช้งานในฟีเจอร์อื่น ข้อมูลเหล่านี้ต้องไม่ hardcode ไว้ในโค้ด <- UC-15 main flow ขั้น 1-3
- FR-SYS-02 ระบบต้องให้ผู้ดูแลระบบสร้าง แก้ไข และปิดใช้งาน system master/reference data ได้ โดยข้อมูลที่ถูกอ้างอิงอยู่ต้องไม่ถูกลบแบบถาวร และต้องเปิดทางให้ปิดใช้งานแทน <- UC-15 main flow ขั้น 4
- FR-SYS-03 ระบบต้องตรวจสอบข้อมูลก่อนบันทึก                                       <- UC-15 main flow ขั้น 5 / acceptance criteria
- FR-SYS-04 เมื่อผู้ดูแลระบบยืนยัน ระบบต้องบันทึกข้อมูล และข้อมูลที่บันทึกต้องถูกนำไปใช้งานในระบบได้ทันที โดยข้อมูลที่ปิดใช้งานแล้วต้องยังใช้กับข้อมูลเก่าได้ แต่ต้องไม่สามารถเลือกใช้กับรายการใหม่ได้ <- UC-15 main flow ขั้น 6-7 / acceptance criteria
- FR-SYS-05 ระบบต้องให้ผู้ดูแลระบบยกเลิกการแก้ไขก่อนบันทึกได้ โดยข้อมูลเดิมไม่เปลี่ยน      <- UC-15 alternative flow
- FR-SYS-06 หากข้อมูลไม่ถูกต้อง ระบบต้องแจ้งผู้ดูแลระบบและไม่บันทึก                     <- UC-15 exception flow
- FR-SYS-07 หากระบบไม่สามารถบันทึกข้อมูลได้ ระบบต้องแจ้งผู้ดูแลระบบว่าบันทึกไม่สำเร็จ
  และคงข้อมูลเดิมไว้                                                              <- UC-15 exception flow

## Quality Requirements
- NFR-ACC-01 ต้องมีการควบคุมสิทธิ์ในการจัดการข้อมูลระบบ
- NFR-DAT-01 ข้อมูลต้องมีความถูกต้องและสอดคล้องกัน โดยต้องรักษาการอ้างอิงของข้อมูลเก่าเมื่อข้อมูล master/reference ถูกปิดใช้งาน
- NFR-BKP-01 ระบบต้องสำรองข้อมูลอย่างน้อยวันละ 1 ครั้ง เก็บย้อนหลังอย่างน้อย 30 วัน มี RPO ไม่เกิน 24 ชั่วโมง และมี RTO ไม่เกิน 4 ชั่วโมง

## Acceptance Criteria
- [ ] AC-SYS-01 (FR-SYS-02)
      Given ผู้ดูแลระบบเข้าสู่ระบบด้วยสิทธิ์ที่จัดการข้อมูลได้
      When  สร้าง แก้ไข หรือปิดใช้งานข้อมูล master/reference แล้วยืนยัน
      Then  ระบบดำเนินการสำเร็จ ข้อมูลที่ปิดใช้งานจะไม่ถูกเลือกใช้กับรายการใหม่ และหากข้อมูลถูกอ้างอิงอยู่ระบบต้องไม่ hard delete พร้อมแจ้งจำนวน/รายการที่อ้างอิง
- [ ] AC-SYS-02 (FR-SYS-03, NFR-DAT-01)
      Given ผู้ดูแลระบบกรอกข้อมูลไม่ถูกต้อง
      When  กดบันทึก
      Then  ระบบตรวจพบก่อนบันทึก แจ้งผู้ดูแลระบบ และไม่บันทึกข้อมูล
- [ ] AC-SYS-03 (FR-SYS-04)
      Given ผู้ดูแลระบบแก้ไขข้อมูลระบบและบันทึกสำเร็จ
      When  ผู้ใช้หรือฟังก์ชันอื่นในระบบเรียกใช้ข้อมูลนั้น
      Then  ระบบใช้ข้อมูลที่แก้ไขล่าสุดทันที ข้อมูลเก่ายังอ้างอิงข้อมูลที่ปิดใช้งานได้ และรายการใหม่ไม่สามารถเลือกข้อมูลที่ปิดใช้งาน
- [ ] AC-SYS-04 (FR-SYS-05)
      Given ผู้ดูแลระบบกำลังแก้ไขข้อมูลและยังไม่บันทึก
      When  เลือกยกเลิก
      Then  ข้อมูลเดิมไม่เปลี่ยนแปลง
- [ ] AC-SYS-05 (FR-SYS-07)
      Given ระบบไม่สามารถบันทึกข้อมูลได้
      When  ผู้ดูแลระบบกดบันทึก
      Then  ระบบแจ้งว่าบันทึกไม่สำเร็จ และข้อมูลเดิมยังคงอยู่
- [ ] AC-SYS-06 (NFR-ACC-01)
      Given ผู้ใช้ไม่มี
      สิทธิ์จัดการข้อมูลระบบ
      When  พยายามเข้าเมนูจัดการข้อมูลระบบ
      Then  ระบบไม่อนุญาต

## Assumptions & Open Questions
- ASM-01 พฤติกรรมเมื่อเกิด exception (แจ้งผู้ดูแลระบบ คงข้อมูลเดิม) เป็นข้อสันนิษฐานของผู้เขียน spec
- ASM-02 ขอบเขตของ UC-15 ครอบคลุม system master/reference data ที่ฟีเจอร์อื่นต้องพึ่งพาอย่างน้อย venues, event categories/types, ประเภท/บทบาทการแสดง และ announcement categories หากมีการใช้งาน และข้อมูลเหล่านี้ต้องจัดการผ่าน UC-15 ไม่ hardcode ในโค้ด
- ASM-03 หากข้อมูล master/reference ถูกอ้างอิงอยู่ ห้าม hard delete ต้องปิดใช้งานแทน โดยข้อมูลเก่ายังอ้างอิงได้และข้อมูลที่ปิดใช้งานไม่สามารถเลือกใช้ในรายการใหม่
- ASM-04 ระบบต้องสำรองข้อมูลอย่างน้อย daily เก็บย้อนหลังอย่างน้อย 30 วัน RPO ไม่เกิน 24 ชั่วโมง และ RTO ไม่เกิน 4 ชั่วโมง
- Q-04 ฟิลด์บังคับและ validation ของ system master/reference data แต่ละประเภทมีอะไรบ้าง? (ต้องถามผู้ดูแลระบบ/ทีมเอง)
- Q-05 หลังบันทึกข้อมูลสำเร็จ คำว่า “ใช้งานได้ทันที” ต้องครอบคลุมทุกหน้าหรือฟังก์ชันในการเรียกใช้ครั้งถัดไปอย่างไร? (ต้องถามทีมเอง)
- Q-06 การควบคุมสิทธิ์ต้องป้องกันเฉพาะเมนู หรือรวม URL/API และกำหนดสิทธิ์แยกตาม action หรือไม่? (ต้องถามผู้ดูแลระบบ/ทีมเอง)
- Q-07 หากการบันทึกหลายรายการล้มเหลวระหว่างทาง ระบบต้อง rollback ทั้งหมดหรือยอมให้บันทึกบางส่วนได้? (ต้องถามทีมเอง)
