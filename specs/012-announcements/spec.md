# Feature: ประกาศข่าวสาร (Announcements)
Spec ID: SPEC-ANN-001 | Source: Use Case Specification UC-12 | Use case: UC-12
Owner: TBD | Status: Draft v2 | Updated: 2026-09-20

## Goal
ผู้จัดงานสร้างและเผยแพร่ประกาศสำหรับอีเว้นต์หรือกลุ่มเป้าหมายที่เกี่ยวข้อง เพื่อให้ผู้ที่เกี่ยวข้องติดตามข่าวสารและรับข้อมูลการเปลี่ยนแปลงได้ทันทีผ่านระบบ/แอป

## Scope
### In scope
- สร้างประกาศ (หัวข้อ รายละเอียด) ตรวจสอบข้อมูล และเผยแพร่
- บันทึกเป็นแบบร่าง
- แสดงข่าวสารที่เผยแพร่แล้วให้ผู้ใช้ที่เกี่ยวข้องอ่าน
### Out of scope
- สร้าง / แก้ไขอีเว้นต์ (UC-10) | การแจ้งผลการพิจารณาใบสมัครให้วง (UC-09)

## Constraints
- PRE-ANN-01 ผู้จัดงานเข้าสู่ระบบ (precondition)
- CON-ACC-01 ต้องมีการควบคุมสิทธิ์การประกาศ

## Requirements
- FR-ANN-01 ระบบต้องให้ผู้จัดงานสร้างประกาศและกรอกหัวข้อ รายละเอียด และกำหนด event_id หรือ target_group ของผู้รับข้อมูล <- UC-12 main flow ขั้น 1-3
- FR-ANN-02 ระบบต้องตรวจสอบข้อมูลของประกาศก่อนเผยแพร่ เช่น หัวข้อและรายละเอียดต้องไม่ว่าง และต้องมี event_id หรือ target_group ที่ชัดเจน <- UC-12 main flow ขั้น 4
- FR-ANN-03 เมื่อผู้จัดงานกดเผยแพร่ ระบบต้องแสดงประกาศเฉพาะแก่ผู้ใช้ที่เกี่ยวข้องกับ event_id หรือ target_group นั้น และส่ง in-app notification ให้ผู้ใช้ที่เกี่ยวข้องทราบทันที โดยสามารถเลือกส่งอีเมลหรือ SMS เพิ่มเติมตามความสำคัญของการเปลี่ยนแปลง <- UC-12 main flow ขั้น 5-6
- FR-ANN-04 ระบบต้องให้ผู้จัดงานบันทึกประกาศเป็นแบบร่างได้ โดยแบบร่างยังไม่แสดงต่อผู้ใช้ และเมื่อประกาศเผยแพร่แล้ว ผู้จัดงานสามารถแก้ไข ซ่อน หรือจัดการประกาศได้ โดยต้องมีประวัติการแก้ไข (edit log) และการซ่อน/soft delete มากกว่าการลบถาวรทันที <- UC-12 alternative flow
- FR-ANN-05 หากระบบไม่สามารถเผยแพร่ข่าวสารได้ ระบบต้องแจ้งผู้จัดงานว่าเผยแพร่ไม่สำเร็จ และไม่แสดงประกาศให้ผู้ใช้เห็น <- UC-12 exception flow
- FR-ANN-06 ระบบต้องอนุญาตให้เฉพาะผู้มีสิทธิ์สร้างและเผยแพร่ประกาศเท่านั้น <- UC-12 NFR

## Quality Requirements
- NFR-DAT-01 ระบบต้องแสดงข่าวสารอย่างถูกต้องตรงกับที่ผู้จัดงานเผยแพร่ และแสดงเฉพาะแก่ผู้ใช้ที่เกี่ยวข้องด้วย
- NFR-ACC-01 ต้องมีการควบคุมสิทธิ์การประกาศ

## Acceptance Criteria
- [ ] AC-ANN-01 (FR-ANN-01)
      Given ผู้จัดงานเข้าสู่ระบบแล้ว
      When  สร้างประกาศโดยกรอกหัวข้อ รายละเอียด และกำหนด event_id หรือ target_group
      Then  ระบบสร้างประกาศได้สำเร็จ
- [ ] AC-ANN-02 (FR-ANN-03)
      Given ผู้จัดงานสร้างประกาศที่ข้อมูลถูกต้อง และระบุกลุ่มผู้รับข้อมูลที่ชัดเจน
      When  กดเผยแพร่
      Then  ประกาศถูกเผยแพร่เฉพาะแก่ผู้ใช้ที่เกี่ยวข้อง และระบบส่ง in-app notification ให้ทราบทันที ส่วนอีเมลหรือ SMS เป็นทางเลือกเพิ่มเติมตามความสำคัญของการเปลี่ยนแปลง
- [ ] AC-ANN-03 (FR-ANN-03, NFR-DAT-01)
      Given ข่าวสารถูกเผยแพร่แล้ว
      When  ผู้ใช้ที่เกี่ยวข้องเปิดดูข่าวสาร
      Then  ผู้ใช้นั้นอ่านข่าวสารได้ และเนื้อหาตรงกับที่เผยแพร่ โดยไม่แสดงให้ผู้ใช้ที่ไม่เกี่ยวข้องเห็น
- [ ] AC-ANN-04 (FR-ANN-04)
      Given ผู้จัดงานสร้างประกาศยังไม่เสร็จ หรือประกาศที่เผยแพร่แล้วมีการแก้ไข/ซ่อน
      When  เลือกบันทึกเป็นแบบร่าง หรือเลือกซ่อน/แก้ไขประกาศที่เผยแพร่แล้ว
      Then  ระบบบันทึกแบบร่างไว้และ/หรือซ่อนประกาศแบบ soft delete พร้อมบันทึกประวัติการแก้ไข (edit log) และไม่ทำลายข้อมูลทันที
- [ ] AC-ANN-05 (FR-ANN-05)
      Given ระบบไม่สามารถเผยแพร่ข่าวสารได้
      When  ผู้จัดงานกดเผยแพร่
      Then  ระบบแจ้งว่าเผยแพร่ไม่สำเร็จ และผู้ใช้ไม่เห็นประกาศนั้น
- [ ] AC-ANN-06 (FR-ANN-06, NFR-ACC-01)
      Given ผู้ใช้ไม่ใช่ผู้จัดงานที่มีสิทธิ์ประกาศ
      When  พยายามสร้างหรือเผยแพร่ประกาศ
      Then  ระบบไม่อนุญาต

## Assumptions & Open Questions
- ASM-01 พฤติกรรมเมื่อเผยแพร่ไม่สำเร็จ (แจ้งผู้จัดงาน ไม่แสดงประกาศ) เป็นข้อสันนิษฐานของผู้เขียน spec
- ASM-02 "แสดงข่าวสาร" หมายถึงแสดงในระบบให้ผู้ใช้เปิดอ่าน และเมื่อมีการเปลี่ยนแปลงต้องมี in-app notification เป็นขั้นต่ำ
- ASM-03 ประกาศต้องมี event_id หรือ target_group เพื่อกำหนดกลุ่มผู้อ่าน และระบบจะแสดงเฉพาะแก่ผู้ใช้ที่เกี่ยวข้องกับอีเว้นต์/กลุ่มนั้นเท่านั้น
- ASM-04 การเปลี่ยนแปลงที่มีผลต่อผู้ใช้ต้องมี in-app notification เป็นขั้นต่ำ; email/SMS ให้พิจารณาเป็นช่องทางเสริมตามความสำคัญของการเปลี่ยนแปลง
- ASM-05 เมื่อประกาศเผยแพร่แล้ว ผู้จัดงานยังสามารถแก้ไข ซ่อน หรือ soft delete ได้ โดยต้องมี edit log และ/หรือป้าย "แก้ไขล่าสุดเมื่อ..." เพื่อให้ผู้อ่านทราบว่ามีการเปลี่ยนแปลง
- Open Questions: ไม่มี (คำถามที่มีการตอบแล้วถูกย้ายเป็น assumption)
