# Feature: สมัครเข้าร่วมแสดง (Band Application)
Spec ID: SPEC-APP-001 | Source: Use Case Specification UC-06 | Use case: UC-06
Owner: TBD | Status: Draft v2 | Updated: 2569-09-20

## Goal
วงดนตรีนักศึกษาสมัครขึ้นแสดงในอีเว้นต์ที่เปิดรับสมัครโดยส่งข้อมูลวงและข้อมูลเพลง/การแสดง
ระบบบันทึกใบสมัครด้วยสถานะรอตรวจสอบ เพื่อให้ผู้จัดงานนำข้อมูลไปพิจารณา

## Scope
### In scope
- เลือกอีเว้นต์ กรอกข้อมูลวง และข้อมูลเพลง/การแสดง
- ตรวจสอบความครบถ้วนของข้อมูล บันทึกใบสมัคร และแสดงสถานะรอตรวจสอบ
### Out of scope
- จัดการข้อมูลวงดนตรี (UC-07) | ตรวจสอบสถานะการสมัคร (UC-08) | ตรวจสอบและอนุมัติวงดนตรี (UC-09)
- เข้าสู่ระบบ (UC-01) - ถือว่าทำสำเร็จแล้วก่อนเข้าฟีเจอร์นี้ (precondition)

## Constraints
- PRE-APP-01 วงเข้าสู่ระบบแล้ว และอีเว้นต์เปิดรับสมัคร (precondition)

## Requirements
- FR-APP-01 ระบบต้องให้วงเลือกอีเว้นต์ที่เปิดรับสมัคร                                <- UC-06 main flow ขั้น 1
- FR-APP-02 ระบบต้องแสดงข้อมูลวงจาก UC-07 ในฟอร์มแบบแก้ไขไม่ได้ และให้วงกรอกข้อมูลเพลง/การแสดงใหม่สำหรับใบสมัครแต่ละใบ โดยข้อมูลบังคับต้องประกอบด้วย ชื่อวง แนวเพลง สมาชิกอย่างน้อย 1 คนพร้อมชื่อและตำแหน่ง/เครื่องดนตรี ผู้ติดต่อพร้อมชื่อและเบอร์โทร รายชื่อเพลงอย่างน้อย 1 เพลงพร้อมระบุว่าเป็นเพลงต้นฉบับหรือคัฟเวอร์และศิลปินเดิมเมื่อเป็นเพลงคัฟเวอร์ และความยาวการแสดงรวม ส่วนข้อมูลความต้องการอุปกรณ์/เวที ลิงก์ตัวอย่างผลงาน และหมายเหตุเป็นข้อมูลไม่บังคับ                         <- UC-06 main flow ขั้น 2-3
- FR-APP-03 เมื่อวงส่งใบสมัคร ระบบต้องตรวจสอบว่าข้อมูลบังคับครบถ้วน และตรวจสอบว่าความยาวการแสดงรวมและจำนวนเพลงไม่เกินค่าที่ผู้จัดงานกำหนด                                 <- UC-06 main flow ขั้น 4-5
- FR-APP-04 เมื่อข้อมูลครบถ้วน ระบบต้องเก็บสำเนาข้อมูลวงและข้อมูลเพลง/การแสดงไว้กับใบสมัคร บันทึกใบสมัครด้วยสถานะ "รอตรวจสอบ" และแสดงสถานะ "รอตรวจสอบ" ให้วงทราบ                                                 <- UC-06 main flow ขั้น 6-7
- FR-APP-05 หากข้อมูลบังคับไม่ครบ หรือข้อมูลวงจาก UC-07 ยังไม่ครบฟิลด์บังคับ ระบบต้องให้วงแก้ไขข้อมูลที่เกี่ยวข้องก่อนส่งใบสมัคร และไม่บันทึกใบสมัคร                   <- UC-06 alternative flow
- FR-APP-06 หากระบบไม่สามารถบันทึกใบสมัครได้ ระบบต้องแจ้งวงว่าส่งใบสมัครไม่สำเร็จ
  และไม่สร้างใบสมัครที่ไม่สมบูรณ์                                                 <- UC-06 exception flow

## Quality Requirements
- NFR-SEC-01 ระบบต้องรักษาข้อมูลของวง โดยข้อมูลวงที่แก้ไขภายหลังต้องไม่เปลี่ยนแปลงข้อมูลสำเนาที่เก็บในใบสมัคร [มาตรการความปลอดภัยเพิ่มเติม: ต้องกำหนด, Q-03]
- NFR-PERF-01 ระบบต้องรองรับการส่งข้อมูลพร้อมกันหลายวง [จำนวนวงพร้อมกันและเวลาตอบสนอง: ต้องกำหนด, Q-03]

## Acceptance Criteria
- [ ] AC-APP-01 (FR-APP-04)
      Given วงเข้าสู่ระบบแล้ว เลือกอีเว้นต์ที่เปิดรับสมัคร และกรอกข้อมูลครบถ้วนโดยไม่เกินข้อจำกัดของอีเว้นต์
      When  วงส่งใบสมัคร
      Then  ระบบบันทึกใบสมัครสำเร็จและผูกกับอีเว้นต์ที่เลือก
- [ ] AC-APP-02 (FR-APP-02, FR-APP-04)
      Given วงส่งใบสมัครสำเร็จ
      When  ตรวจสอบข้อมูลที่บันทึก
      Then  สำเนาข้อมูลวงจาก UC-07 และข้อมูลเพลง/การแสดงถูกบันทึกไว้กับใบสมัครครบถ้วน
- [ ] AC-APP-03 (FR-APP-04)
      Given ระบบบันทึกใบสมัครแล้ว
      When  ระบบตอบกลับผู้ใช้
      Then  แสดงสถานะ "รอตรวจสอบ"
- [ ] AC-APP-04 (FR-APP-05)
      Given วงกรอกข้อมูลบังคับไม่ครบ หรือความยาวการแสดงรวม/จำนวนเพลงเกินข้อจำกัดของอีเว้นต์
      When  กดส่งใบสมัคร
      Then  ระบบให้แก้ไขข้อมูลก่อนส่ง และไม่บันทึกใบสมัคร
- [ ] AC-APP-05 (FR-APP-06)
      Given ระบบไม่สามารถบันทึกใบสมัครได้
      When  วงส่งใบสมัคร
      Then  ระบบแจ้งว่าส่งไม่สำเร็จ และไม่มีใบสมัครที่ไม่สมบูรณ์ในระบบ

## Assumptions & Open Questions
- ASM-01 พฤติกรรมเมื่อบันทึกไม่สำเร็จ (แจ้งวง ไม่สร้างใบสมัครที่ไม่สมบูรณ์) เป็นข้อสันนิษฐานของผู้เขียน spec
- ASM-02 ข้อมูลวงในใบสมัครดึงจาก UC-07 และแสดงแบบแก้ไขไม่ได้ หากข้อมูลวงยังไม่ครบฟิลด์บังคับ ต้องให้วงไปแก้ไขใน UC-07 ก่อนจึงส่งใบสมัครได้
- ASM-03 เมื่อส่งใบสมัคร ระบบเก็บสำเนาข้อมูลวงล่าสุดไว้กับใบสมัคร การแก้ข้อมูลวงภายหลังไม่กระทบใบสมัครเดิม และหากผู้จัดงานส่งกลับให้แก้ไข การส่งใหม่จะเก็บสำเนาข้อมูลวงล่าสุดเป็นข้อมูลของการส่งใหม่นั้น
- ASM-04 ข้อมูลบังคับของใบสมัครคือ ชื่อวง แนวเพลง สมาชิกอย่างน้อย 1 คนพร้อมชื่อและตำแหน่ง/เครื่องดนตรี ผู้ติดต่อพร้อมชื่อและเบอร์โทร รายชื่อเพลงอย่างน้อย 1 เพลงพร้อมประเภทเพลงและศิลปินเดิมเมื่อเป็นเพลงคัฟเวอร์ และความยาวการแสดงรวม
- ASM-05 ความต้องการอุปกรณ์/เวที ลิงก์ตัวอย่างผลงาน และหมายเหตุเป็นข้อมูลไม่บังคับ
- ASM-06 สถานะของใบสมัครที่บันทึกสำเร็จมีค่า "รอตรวจสอบ" และระบบต้องแสดงข้อความนี้ตรงตัวใน UC-06, UC-08 และ UC-09 โดยสถานะที่ใช้ได้มี 3 ค่า คือ "รอตรวจสอบ", "อนุมัติ" และ "ปฏิเสธ"; หากบันทึกไม่สำเร็จจะไม่สร้างใบสมัครและไม่มีสถานะ
- Q-01 วงสามารถสมัครอีเว้นต์เดียวกันซ้ำได้หรือไม่ และถ้าไม่ได้ ระบบต้องจัดการใบสมัครซ้ำอย่างไร?
- Q-02 เวลาแสดงสูงสุดและจำนวนเพลงสูงสุดที่ผู้จัดงานกำหนดมีค่าเป็นเท่าใด และกำหนดแยกตามอีเว้นต์ได้หรือไม่?
- Q-03 มาตรการรักษาความปลอดภัยของข้อมูลวง และจำนวนวงที่ต้องรองรับพร้อมกัน/เวลาตอบสนองเป้าหมายคือเท่าใด?
