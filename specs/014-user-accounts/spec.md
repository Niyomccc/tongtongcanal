# Feature: จัดการบัญชีผู้ใช้ (User Account Management)
Spec ID: SPEC-ACC-001 | Source: Use Case Specification UC-14 | Use case: UC-14
Owner: TBD | Status: Draft v2 | Updated: 2026-09-20

## Goal
ผู้ดูแลระบบเพิ่ม แก้ไข ระงับ และเปลี่ยนสิทธิ์บัญชีผู้ใช้ เพื่อควบคุมบัญชีและให้ผู้ใช้ใช้งานได้อย่างปลอดภัย

## Scope
### In scope
- เปิดรายการบัญชี เลือกบัญชี และเพิ่ม / แก้ไข / ระงับบัญชี
- เปลี่ยนสิทธิ์ของผู้ใช้
- จำกัดการเข้าถึงเมนูนี้เฉพาะผู้ดูแลระบบ
### Out of scope
- สมัครสมาชิก / เข้าสู่ระบบโดยผู้ใช้ (UC-01) | จัดการข้อมูลระบบ (UC-15)

## Constraints
- PRE-ACC-01 ผู้ดูแลระบบเข้าสู่ระบบผ่านหน้าเข้าสู่ระบบเดียวกับ UC-01 ด้วย authentication flow เดียวกัน และต้องมีสิทธิ์ Admin (precondition); บัญชี Admin ต้องถูกสร้าง/กำหนดสิทธิ์ผ่าน UC-14 เท่านั้น โดย Admin คนแรกต้องถูก seed ตั้งแต่ติดตั้งระบบ

## Requirements
- FR-ACC-01 ระบบต้องแสดงรายการบัญชีให้ผู้ดูแลระบบเลือกบัญชี                         <- UC-14 main flow ขั้น 1-2
- FR-ACC-02 ระบบต้องให้ผู้ดูแลระบบเพิ่ม แก้ไข ระงับ และยกเลิกการระงับบัญชีผู้ใช้ได้ โดยเมื่อระงับบัญชี ระบบต้อง force logout/invalidate session ของผู้ใช้นั้นทันที และไม่ปล่อยให้ session เดิมทำงานต่อจนหมดอายุเอง <- UC-14 main flow ขั้น 3
- FR-ACC-03 ระบบต้องตรวจสอบข้อมูลก่อนบันทึก และบันทึกข้อมูลบัญชีเมื่อข้อมูลถูกต้อง        <- UC-14 main flow ขั้น 4-5
- FR-ACC-04 ระบบต้องให้ผู้ดูแลระบบเปลี่ยนสิทธิ์ของผู้ใช้ได้                            <- UC-14 acceptance criteria
- FR-ACC-05 ระบบต้องให้ผู้ดูแลระบบยกเลิกการเปลี่ยนแปลงก่อนบันทึกได้ โดยข้อมูลบัญชีไม่เปลี่ยน <- UC-14 alternative flow
- FR-ACC-06 หากไม่พบผู้ใช้หรือข้อมูลไม่ถูกต้อง ระบบต้องแจ้งผู้ดูแลระบบและไม่บันทึก         <- UC-14 exception flow
- FR-ACC-07 ระบบต้องไม่ให้ผู้ที่ไม่มีสิทธิ์ Admin เข้าถึงเมนูจัดการบัญชีผู้ใช้              <- UC-14 acceptance criteria

## Quality Requirements
- NFR-SEC-01 ต้องตรวจสอบสิทธิ์ Admin ก่อนทุก action ที่แก้ไขบัญชีหรือสิทธิ์ และบันทึก audit log ทุกครั้งที่มีการเปลี่ยนแปลงบัญชีหรือสิทธิ์ โดย log ต้องเก็บอย่างน้อย actor, action, target user, timestamp, old value และ new value และต้องเป็น immutable แก้ไขหรือลบไม่ได้แม้แต่โดย Admin
- NFR-ACC-01 ต้องตรวจสอบสิทธิ์การเข้าถึงฝั่งระบบก่อนทุก action ที่แก้ไขบัญชีหรือสิทธิ์

## Acceptance Criteria
- [ ] AC-ACC-01 (FR-ACC-02, FR-ACC-03)
      Given ผู้ดูแลระบบเข้าสู่ระบบด้วยสิทธิ์ Admin
      When  เพิ่ม แก้ไข หรือระงับบัญชีผู้ใช้ แล้วบันทึก
      Then  ระบบบันทึกข้อมูลบัญชีที่ปรับปรุงสำเร็จ และหากเป็นการระงับต้อง force logout/invalidate session ของผู้ใช้ทันที
- [ ] AC-ACC-02 (FR-ACC-04)
      Given ผู้ดูแลระบบเลือกบัญชีผู้ใช้
      When  เปลี่ยนสิทธิ์ของผู้ใช้และบันทึก
      Then  ผู้ใช้นั้นได้รับสิทธิ์ใหม่ตามที่กำหนด และระบบบันทึก audit log ที่ immutable โดยมี actor, action, target user, timestamp, old value และ new value
- [ ] AC-ACC-03 (FR-ACC-05)
      Given ผู้ดูแลระบบกำลังแก้ไขบัญชีและยังไม่บันทึก
      When  เลือกยกเลิก
      Then  ข้อมูลบัญชีไม่เปลี่ยนแปลง
- [ ] AC-ACC-04 (FR-ACC-06)
      Given ไม่พบผู้ใช้ที่เลือก หรือข้อมูลที่กรอกไม่ถูกต้อง
      When  ผู้ดูแลระบบกดบันทึก
      Then  ระบบแจ้งผู้ดูแลระบบ และไม่บันทึกข้อมูล
- [ ] AC-ACC-05 (FR-ACC-07, NFR-ACC-01)
      Given ผู้ใช้ไม่มีสิทธิ์ Admin
      When  พยายามเข้าเมนูจัดการบัญชีผู้ใช้
      Then  ระบบไม่อนุญาตให้เข้าถึงเมนู

## Assumptions & Open Questions
- ASM-01 พฤติกรรมเมื่อเกิด exception (แจ้งผู้ดูแลระบบ ไม่บันทึก) เป็นข้อสันนิษฐานของผู้เขียน spec
- ASM-02 ผู้ดูแลระบบใช้หน้าเข้าสู่ระบบและ authentication flow เดียวกับ UC-01 แต่ไม่สามารถสมัครสมาชิกเป็น Admin ผ่านหน้านั้นได้ บัญชี Admin ต้องถูกสร้าง/กำหนดสิทธิ์ผ่าน UC-14 และ Admin คนแรกต้องถูก seed ตั้งแต่ติดตั้งระบบ
- ASM-03 การระงับบัญชีมีผลทันทีต่อผู้ใช้ที่กำลังใช้งาน โดยระบบต้อง force logout/invalidate session และ Admin สามารถยกเลิกการระงับเพื่อคืนสิทธิ์ให้ผู้ใช้ได้
- ASM-04 ทุก action ที่แก้ไขบัญชีหรือสิทธิ์ต้องผ่าน authorization check ของ Admin และทุกการเปลี่ยนแปลงต้องมี immutable audit log ที่เก็บ actor, action, target user, timestamp, old value และ new value
- Q-02 การลบบัญชีผู้ใช้อยู่ในขอบเขตของฟีเจอร์นี้หรือไม่? (ต้องถามทีมเอง)
- Q-03 ฟิลด์บังคับและ validation ของการเพิ่ม แก้ไข และระงับบัญชีแต่ละแบบมีอะไรบ้าง? (ต้องถามผู้ดูแลระบบ/ทีมเอง)
- Q-04 ผู้ดูแลระบบสามารถเปลี่ยนสิทธิ์ผู้ใช้เป็นสิทธิ์ใดได้บ้าง และสามารถเปลี่ยนสิทธิ์ของบัญชี Admin ได้หรือไม่? (ต้องถามผู้ดูแลระบบ/ทีมเอง)
- Q-05 การป้องกันผู้ไม่มีสิทธิ์ต้องครอบคลุมเฉพาะเมนูบนหน้าจอ หรือรวม URL และ API โดยตรงด้วย? (ต้องถามทีมเอง)
- Q-06 รายการบัญชีผู้ใช้ต้องแสดงข้อมูลและรองรับการค้นหาหรือเรียงลำดับด้วยเงื่อนไขใดบ้าง? (ต้องถามผู้ดูแลระบบ/ทีมเอง)
