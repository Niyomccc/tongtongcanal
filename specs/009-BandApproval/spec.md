# Feature: ตรวจสอบและอนุมัติวงดนตรี (Band Approval)
Spec ID: SPEC-APR-001 | Source: Use Case Specification UC-09 | Use case: UC-09
Owner: TBD | Status: Draft v2 | Updated: 2569-09-20

## Goal
ผู้จัดงานตรวจสอบใบสมัครและข้อมูลวง แล้วอนุมัติหรือปฏิเสธเพื่อคัดเลือกวงที่เหมาะสม
โดยระบบแจ้งผลให้วงทราบผ่านหน้าสถานะการสมัคร และเก็บประวัติการอนุมัติอย่างครบถ้วน

## Scope
### In scope
- เปิดรายการใบสมัคร ตรวจสอบข้อมูลวง สมาชิก และรายละเอียดการแสดง
- อนุมัติ / ปฏิเสธ / ส่งใบสมัครกลับให้วงแก้ไข
- บันทึกผลและประวัติการอนุมัติ และแจ้งผลให้วง
### Out of scope
- สมัครเข้าร่วมแสดง (UC-06) | ตรวจสอบสถานะการสมัคร (UC-08) | จัดตารางการแสดง (UC-11)

## Constraints
- PRE-APR-01 มีวงส่งใบสมัครเข้ามา (precondition)
- CON-ACC-01 เฉพาะผู้จัดงานที่ได้รับสิทธิ์เท่านั้นที่ตรวจสอบและอนุมัติได้

## Requirements
- FR-APR-01 ระบบต้องแสดงรายการใบสมัครให้ผู้จัดงานเลือกวง                            <- UC-09 main flow ขั้น 1-2
- FR-APR-02 ระบบต้องแสดงข้อมูลวง สมาชิก และรายละเอียดการแสดงเพื่อให้ผู้จัดงานตรวจสอบ     <- UC-09 main flow ขั้น 3-4
- FR-APR-03 ระบบต้องให้ผู้จัดงานเลือกอนุมัติหรือปฏิเสธ หรือส่งกลับให้วงแก้ไข และบันทึกผล หากข้อความที่ระบุเหตุผลหรือสิ่งที่ต้องแก้ไขเป็นค่าว่างหรือช่องว่างล้วน ระบบต้องไม่บันทึกผลและไม่เปลี่ยนสถานะ <- UC-09 main flow ขั้น 5-6
- FR-APR-04 ระบบต้องแจ้งผลการพิจารณาให้วงทราบผ่านหน้าสถานะการสมัครของใบสมัครตนเอง และเมื่อระบบบันทึกผลแล้ว วงต้องเห็นสถานะใหม่พร้อมข้อความจากผู้จัดงานในหน้านั้น ใช้ช่องทางอีเมลเป็นเสริมเท่านั้น และอีเมลที่ส่งไม่สำเร็จไม่ควรทำให้ผลการพิจารณาหยุดหรือถูกยกเลิก <- UC-09 main flow ขั้น 7
- FR-APR-05 ระบบต้องให้ผู้จัดงานส่งใบสมัครกลับไปให้วงแก้ไขข้อมูลได้พร้อมข้อความที่ระบุสิ่งที่ต้องแก้ไข และวงสามารถแก้ไขทุกฟิลด์ของข้อมูลเพลง/การแสดงในใบสมัครได้ ไม่จำกัดเฉพาะจุดที่ผู้จัดงานระบุ เมื่อวงส่งใหม่ ใบสมัครเดิมกลับเป็น "รอตรวจสอบ" โดยไม่สร้างใบสมัครใหม่ <- UC-09 alternative flow
- FR-APR-06 หากข้อมูลวงไม่ครบหรือไม่สามารถตรวจสอบได้ ระบบต้องแจ้งผู้จัดงาน
  และไม่บันทึกผลอนุมัติ/ปฏิเสธ                                                    <- UC-09 exception flow
- FR-APR-07 ระบบต้องเก็บประวัติการอนุมัติของแต่ละใบสมัครอย่างไม่สามารถแก้ไขหรือลบโดยทุกบทบาท และต้องมีข้อมูลใบสมัครและอีเว้นต์ ผู้พิจารณา เวลาที่ทำรายการ การกระทำ (อนุมัติ / ปฏิเสธ / ส่งกลับแก้ไข / วงส่งใหม่) สถานะก่อนและหลัง เหตุผลหรือข้อความที่ให้วง และสำเนาข้อมูลใบสมัครตอนตัดสิน พร้อมเก็บอย่างน้อย 1 ปีหลังอีเว้นต์จบหรือตามระเบียบของมหาวิทยาลัย แล้วลบหรือทำให้ไม่ระบุตัวตน <- UC-09 NFR

## Quality Requirements
- NFR-ACC-01 ต้องกำหนดสิทธิ์ผู้จัดงานในการตรวจสอบและอนุมัติ
- NFR-AUD-01 ระบบต้องเก็บประวัติการอนุมัติที่ครอบคลุมข้อมูลดังกล่าวตาม FR-APR-07 และให้ผู้จัดงานที่มีสิทธิ์เห็นประวัติได้ ส่วนวงเห็นเฉพาะสถานะและข้อความของใบสมัครตนเองเท่านั้น

## Acceptance Criteria
- [ ] AC-APR-01 (FR-APR-02)
      Given มีวงส่งใบสมัครเข้ามา
      When  ผู้จัดงานเปิดใบสมัครของวง
      Then  ผู้จัดงานเห็นข้อมูลวง สมาชิก และรายละเอียดการแสดงเพื่อตรวจสอบ
- [ ] AC-APR-02 (FR-APR-03)
      Given ผู้จัดงานตรวจสอบใบสมัครแล้ว
      When  เลือกอนุมัติ
      Then  ระบบบันทึกสถานะใบสมัครเป็น "อนุมัติ"
- [ ] AC-APR-03 (FR-APR-03)
      Given ผู้จัดงานตรวจสอบใบสมัครแล้ว
      When  เลือกปฏิเสธ และกรอกเหตุผลที่ไม่ว่าง
      Then  ระบบบันทึกสถานะใบสมัครเป็น "ปฏิเสธ" และบันทึกเหตุผลไว้ในประวัติการอนุมัติ
- [ ] AC-APR-04 (FR-APR-04)
      Given ผู้จัดงานบันทึกผลอนุมัติหรือปฏิเสธหรือส่งกลับแก้ไขแล้ว
      When  การบันทึกเสร็จสิ้น
      Then  วงเห็นสถานะใหม่ของใบสมัครตนเองพร้อมข้อความจากผู้จัดงานในหน้าสถานะการสมัคร และระบบแสดงตัวบอกว่ามีสถานะใหม่ที่ยังไม่ได้เปิดดู
- [ ] AC-APR-05 (FR-APR-05)
      Given ข้อมูลของวงต้องได้รับการแก้ไข
      When  ผู้จัดงานส่งใบสมัครกลับพร้อมข้อความที่ระบุสิ่งที่ต้องแก้ไข
      Then  วงได้รับแจ้งในหน้าสถานะการสมัคร และสามารถแก้ไขทุกฟิลด์ของข้อมูลเพลง/การแสดงในใบสมัครได้
- [ ] AC-APR-06 (FR-APR-06)
      Given ข้อมูลวงไม่ครบหรือไม่สามารถตรวจสอบได้
      When  ผู้จัดงานพยายามอนุมัติหรือปฏิเสธ
      Then  ระบบแจ้งผู้จัดงาน และไม่บันทึกผลการพิจารณา
- [ ] AC-APR-07 (FR-APR-07, NFR-AUD-01)
      Given ผู้จัดงานบันทึกผลการพิจารณา
      When  การบันทึกเสร็จสิ้น
      Then  มีประวัติการอนุมัติของใบสมัครนั้นในระบบ พร้อมรายละเอียดตาม FR-APR-07 และผู้จัดงานที่มีสิทธิ์เห็นประวัติได้ ขณะที่วงเห็นเฉพาะสถานะและข้อความของตนเอง
- [ ] AC-APR-08 (NFR-ACC-01)
      Given ผู้ใช้ไม่ใช่ผู้จัดงานที่ได้รับสิทธิ์
      When  พยายามเข้าถึงรายการใบสมัครหรืออนุมัติวง
      Then  ระบบไม่อนุญาต

## Assumptions & Open Questions
- ASM-01 พฤติกรรมเมื่อข้อมูลวงไม่ครบ (แจ้งผู้จัดงาน ไม่บันทึกผล) เป็นข้อสันนิษฐานของผู้เขียน spec
- ASM-02 การแจ้งผลให้วงทราบหลักคือผ่านหน้าสถานะการสมัครของใบสมัครตนเอง และถือว่าการแจ้งสำเร็จเมื่อระบบบันทึกผลแล้วและวงเห็นสถานะใหม่พร้อมข้อความจากผู้จัดงานในหน้านั้น
- ASM-03 ช่องทางอีเมลเป็นเสริมเท่านั้น และหากอีเมลส่งไม่สำเร็จ ผลการพิจารณายังคงถูกบันทึกและแสดงในระบบตามเดิม
- ASM-04 หากผู้จัดงานส่งใบสมัครกลับให้แก้ไข ต้องระบุข้อความที่ต้องแก้ไข และข้อความต้องไม่ว่างและไม่ใช่ช่องว่างล้วน ถ้าข้อมูลว่าง ระบบไม่บันทึกผลและไม่เปลี่ยนสถานะ
- ASM-05 เมื่อวงแก้ไขแล้วส่งใหม่ ใบสมัครเดิมกลับเป็น "รอตรวจสอบ" และผู้จัดงานต้องตรวจทั้งใบอีกครั้ง ไม่สร้างใบสมัครใหม่ และอีเว้นต์ที่สมัครเปลี่ยนไม่ได้
- ASM-06 ประวัติการอนุมัติเป็นข้อมูลที่ไม่สามารถแก้ไขหรือลบโดยทุกบทบาท และต้องเก็บอย่างน้อย 1 ปีหลังอีเว้นต์จบหรือตามระเบียบของมหาวิทยาลัย แล้วลบหรือทำให้ไม่ระบุตัวตน
- ASM-07 ผู้จัดงานสามารถส่งกลับให้วงแก้ไขได้ทุกฟิลด์ของข้อมูลเพลง/การแสดงในใบสมัคร และข้อมูลวงที่ต้องแก้ไขอยู่ใน UC-07 โดยระบบดึงข้อมูลล่าสุดมาเป็นสำเนาใหม่ตอนส่ง
