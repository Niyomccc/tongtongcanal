
## 1. สรุปแนวทาง

1. ตรวจสอบ session ของผู้ใช้และอีเว้นต์ที่เปิดให้ลงทะเบียนตาม precondition
2. ให้ผู้ใช้เลือกอีเว้นต์และอ่านจำนวนที่นั่งทั้งหมด จำนวนผู้ลงทะเบียน และจำนวนที่ว่าง
3. แสดงจำนวนที่ว่าง และแจ้งเตือนเมื่อจำนวนที่นั่งอยู่ในเกณฑ์ [N] ที่นั่ง หรือ [P]% ของความจุ
4. เมื่อผู้ใช้ยืนยัน ให้ตรวจสอบการลงทะเบียนซ้ำและตรวจสอบจำนวนที่ว่างอีกครั้งก่อนบันทึก
5. บันทึกผู้ใช้กับอีเว้นต์แบบที่ไม่ทำให้จำนวนผู้ลงทะเบียนเกินที่นั่ง แม้มีการยืนยันพร้อมกัน
6. แสดงผลสำเร็จเมื่อบันทึกได้ หรือแจ้งว่าที่นั่งเต็มเมื่อไม่สามารถลงทะเบียนได้

ค่า [N] และ [P] ยังไม่ถูกกำหนดใน spec จึงยังไม่สามารถทดสอบเกณฑ์การแจ้งเตือนของ FR-REG-03 และ AC-REG-03 ได้

## 2. เทคโนโลยีที่ใช้

| สิ่งที่เลือก | มาจาก | หมายเหตุ |
|---|---|---|
| ภาษาและ framework ของส่วนติดต่อผู้ใช้ | ทีมเลือกเอง ไม่ได้มาจาก spec | ใช้สร้างหน้าจอเลือกอีเว้นต์และแสดงผลการลงทะเบียน |
| ภาษาและ framework ของส่วนประมวลผล | ทีมเลือกเอง ไม่ได้มาจาก spec | ใช้ตรวจสอบสิทธิ์ ตรวจสอบซ้ำ และบันทึกการลงทะเบียน |
| ฐานข้อมูลที่รองรับการตรวจสอบและบันทึกพร้อมกัน | ทีมเลือกเอง ไม่ได้มาจาก spec | ต้องรองรับการไม่ให้จำนวนผู้ลงทะเบียนเกินจำนวนที่นั่งตาม FR-REG-04 และ ASM-03 |

## 3. โมเดลข้อมูล

| Entity | ฟิลด์หลัก | รองรับ |
|---|---|---|
| Event | `event_id`, สถานะเปิดให้ลงทะเบียน, `capacity` | PRE-REG-01, FR-REG-01, ASM-01 |
| User | `user_id`, ข้อมูลผู้ใช้ที่ยืนยันตัวตนแล้ว | PRE-REG-01, FR-REG-02, NFR-SEC-01 |
| Registration | `registration_id`, `event_id`, `user_id`, ข้อมูลผู้ใช้ที่ยืนยัน | FR-REG-02, FR-REG-05, NFR-DAT-01 |

หมายเหตุ: ต้องมีการตรวจไม่ให้คู่ `user_id` กับ `event_id` ซ้ำตาม ASM-02 และต้องมีการตรวจจำนวนที่นั่งพร้อมกับการสร้าง `Registration` ตาม ASM-03 การกำหนดชื่อฟิลด์จริงและข้อมูลผู้ใช้ที่จะเก็บยังรอคำตอบ Q-02

## 4. API / หน้าจอ

| รายการ | Input / Output หลัก | รองรับ |
|---|---|---|
| ตรวจสอบ session | Input: session ของผู้ใช้; Output: ผู้ใช้ที่เข้าสู่ระบบแล้ว | PRE-REG-01 |
| `GET` รายการอีเว้นต์ที่เปิดให้ลงทะเบียน | Output: อีเว้นต์ที่เลือกได้ พร้อมความจุและจำนวนที่ว่าง | FR-REG-01 |
| `GET` จำนวนที่ว่างของอีเว้นต์ | Input: `event_id`; Output: ความจุ จำนวนผู้ลงทะเบียน และจำนวนที่ว่าง | FR-REG-01, FR-REG-03, AC-REG-03 |
| `POST` ยืนยันการลงทะเบียน | Input: `event_id`, ผู้ใช้ที่เข้าสู่ระบบ; Output: ผลสำเร็จ หรือเหตุผลที่ปฏิเสธ | FR-REG-02, FR-REG-04, FR-REG-05 |
| หน้าจอเลือกอีเว้นต์ | แสดงรายการอีเว้นต์และให้อีเว้นต์ที่ผู้ใช้เลือก | FR-REG-01 |
| หน้าจอรายละเอียดการลงทะเบียน | แสดงจำนวนที่ว่างและข้อความเตือนตามเกณฑ์ที่กำหนด | FR-REG-01, FR-REG-03 |
| หน้าจอผลการลงทะเบียน | แสดงผลสำเร็จ หรือแจ้งว่าที่นั่งเต็ม/ลงทะเบียนซ้ำ | FR-REG-02, FR-REG-04, FR-REG-05, Q-04 |

รูปแบบข้อมูลผลการลงทะเบียนสำเร็จยังระบุไม่ได้จนกว่าจะตอบ Q-04

## 5. ตารางตรวจ Constraints และ Assumptions

| ID | ถูกนำไปใช้ที่ไหนใน plan | สถานะ |
|---|---|---|
| PRE-REG-01 | ตรวจ session ก่อนแสดงรายการอีเว้นต์และก่อนส่งคำขอลงทะเบียน | ใช้แล้ว |
| ASM-01 | อ่านความจุจากข้อมูลอีเว้นต์ | ใช้แล้ว |
| ASM-02 | ตรวจความซ้ำด้วยผู้ใช้เดียวกันในอีเว้นต์เดียวกัน | ใช้แล้ว |
| ASM-03 | ตรวจจำนวนที่ว่างและบันทึกการลงทะเบียนในขั้นตอนเดียวกันตามกลไกที่ทีมเลือก | ใช้แล้วในระดับข้อกำหนด |
| ASM-04 | จำกัดการอ่านข้อมูลผู้ลงทะเบียนเฉพาะผู้ใช้ที่เกี่ยวข้องและผู้จัดงาน | ใช้แล้ว |

รายละเอียดกลไก concurrency, มาตรการความปลอดภัยเพิ่มเติม และโครงสร้างข้อมูลจริงเป็นเรื่องที่ทีมเลือกเองหรือรอคำตอบ Q-02/Q-03

## 6. แผนทดสอบจาก Acceptance Criteria

| AC ID | ชื่อ test | ทดสอบอย่างไร |
|---|---|---|
| AC-REG-01 | `test_AC_REG_01_register_available_event` | เตรียมผู้ใช้ที่เข้าสู่ระบบ อีเว้นต์เปิดและมีที่ว่าง ยืนยันการลงทะเบียน แล้วตรวจว่ามีรายการและแสดงผลสำเร็จ |
| AC-REG-02 | `test_AC_REG_02_store_confirmed_registration_data` | ลงทะเบียนสำเร็จ แล้วตรวจว่าข้อมูลผู้ลงทะเบียนตรงกับข้อมูลที่ผู้ใช้ยืนยัน |
| AC-REG-03 | `test_AC_REG_03_show_remaining_seats_when_below_threshold` | ใช้ค่าขีดจำกัดจริงของ [N] หรือ [P]% แล้วตรวจว่าระบบแจ้งจำนวนที่นั่งที่เหลือ; ยังรันไม่ได้จนกว่าจะกำหนดค่า |
| AC-REG-04 | `test_AC_REG_04_reject_duplicate_registration` | สร้างรายการลงทะเบียนเดิม แล้วส่งคำขอซ้ำ ตรวจว่าไม่อนุญาตและไม่มีรายการซ้ำ |
| AC-REG-05 | `test_AC_REG_05_reject_full_event_and_race_for_last_seat` | ทดสอบอีเว้นต์เต็ม และทดสอบคำขอพร้อมกันที่เหลือหนึ่งที่นั่ง ตรวจว่าสำเร็จเพียงคนเดียว คำขออื่นถูกปฏิเสธ แจ้งว่าที่นั่งเต็ม และจำนวนไม่เกินความจุ |

NFR-SEC-01 ต้องทดสอบสิทธิ์การเข้าถึงข้อมูลตาม ASM-04 ส่วนมาตรการเพิ่มเติมยังทดสอบไม่ได้จนกว่าจะตอบ Q-03

## 7. ลำดับงาน

1. ตรวจ session และสถานะเปิดให้ลงทะเบียนของอีเว้นต์ (PRE-REG-01)
2. แสดงรายการอีเว้นต์ ให้ผู้ใช้เลือก และอ่านจำนวนที่ว่าง (FR-REG-01)
3. แสดงข้อความจำนวนที่เหลือเมื่อเข้าเกณฑ์ [N] หรือ [P]% (FR-REG-03, AC-REG-03)
4. เมื่อยืนยัน ตรวจว่าผู้ใช้ลงทะเบียนอีเว้นต์นี้แล้วหรือไม่ (FR-REG-05, AC-REG-04)
5. ตรวจจำนวนที่ว่างซ้ำในจุดบันทึก และทำให้การตรวจสอบกับการเพิ่มรายการไม่ทำให้เกินความจุ (FR-REG-04, ASM-03)
6. บันทึกรายการลงทะเบียนและข้อมูลที่ผู้ใช้ยืนยัน (FR-REG-02, NFR-DAT-01)
7. แสดงผลสำเร็จ หรือปฏิเสธพร้อมเหตุผลว่าอีเว้นต์เต็ม/ลงทะเบียนซ้ำ (FR-REG-02, FR-REG-04, FR-REG-05)
8. ตรวจสิทธิ์การเข้าถึงข้อมูลผู้ลงทะเบียนตามผู้ใช้ที่เกี่ยวข้องและผู้จัดงาน (NFR-SEC-01, ASM-04)
9. เขียนและรันทดสอบตาม AC-REG-01 ถึง AC-REG-05 เมื่อมีค่าจริงที่จำเป็น

## 8. สิ่งที่ยังทำไม่ได้หรือรอคำตอบ

- Q-01 ยังไม่กำหนดค่า [N] หรือ [P]% จึงยังทดสอบ FR-REG-03 และ AC-REG-03 ไม่ได้
- Q-02 ยังไม่ทราบฟิลด์ข้อมูลผู้ลงทะเบียนและข้อมูลที่ต้องตรงกับการยืนยัน จึงยังสรุป schema จริงและรายละเอียดการตรวจ AC-REG-02 ไม่ได้
- Q-03 ยังไม่ทราบมาตรการความปลอดภัยเพิ่มเติม จึงยังวางแผนทดสอบมาตรการนอกเหนือจากการจำกัดสิทธิ์ไม่ได้
- Q-04 ยังไม่ทราบข้อมูลที่ต้องแสดงเมื่อสำเร็จ จึงยังสรุปรายละเอียด output ของหน้าผลการลงทะเบียนไม่ได้
- Q-05 ยังไม่ยืนยันคำเรียกและสิทธิ์ของนักศึกษา/ผู้ชม จึงยังไม่กำหนดกฎสิทธิ์เพิ่มเติมนอกเหนือจาก PRE-REG-01
